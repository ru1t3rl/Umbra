# Assumptions

Ambiguities resolved under KISS (spec section 0). Each entry gives its ID, the assumption, the reason, and when to revisit.
Entries that become architectural decisions move to `docs/adr/`.

## M0 Foundations (recorded 2026-10-17 by architect, plan `docs/plans/M0.md`)

| ID | Assumption | Reason | Revisit when |
|---|---|---|---|
| ASM-001 | Library crates live in `crates/<name>/`. Tooling lives in `xtask/`. Reference plugins go in `examples/plugins/` (M4). | Matches the `add-crate` skill. Section 4 names crates but no paths. | Never, unless the workspace layout changes |
| ASM-002 | Repo tooling runs as `cargo xtask <cmd>`. `xtask` is a workspace member binary (aliased in `.cargo/config.toml`) and may use `anyhow`. It may depend on no workspace crate in M0. | The skills already call `cargo xtask`. A Rust tool works the same on Windows and Linux (build-engineer rule). | M4/M5, when `gen-header`/`gen-api` may need workspace crates (the rule change is reviewed) |
| ASM-003 | CI runs on GitHub Actions. No remote is configured yet. | The build-engineer default, and the most common choice. | If the human picks another CI provider |
| ASM-004 | The toolchain is pinned in `rust-toolchain.toml` to the latest stable at the time of WI-1 (with components `rustfmt` and `clippy`). Edition 2024, resolver 3. `rust-version` equals the pinned version. | Reproducible builds (`--locked`). One MSRV to test. | On deliberate toolchain bumps |
| ASM-005 | `check-deps` has two dependency passes. (1) Direct: every declared edge of every kind (normal, build, dev, target-specific, optional, renamed) from `cargo metadata --no-deps` is checked against the allow-list of its crate; a workspace crate missing from the rule table is a violation. (2) Resolved (revised 2026-10-17, review of 0a25b26): `cargo metadata --offline --locked --all-features` (no `--filter-platform`, so all platforms and all optional edges) gives the graph that is actually linked, by package id. For each member, a direct edge to a member must be in its allow-list, and a member reached through non-member packages (members are not expanded) must be in the transitive closure of its allow-list. Because every member-to-member segment is checked by (1) or (2) and the allowed graph is closed and acyclic (rule-table self-test), the transitive guarantee of REQ-A-2/REQ-A-3 now comes from the resolved check, not from the self-test alone. Dev edges are walked from the start member only (cargo resolves dev-dependencies of members only). The resolved pass needs a current `Cargo.lock` and all dependencies in the local cache (`cargo fetch --locked`); otherwise `check-deps` exits 2, it never skips the pass. Cargo runs in the directory of the checked manifest, so `.cargo/config.toml` `[patch]` entries are applied as for a build there. | The direct pass gives precise diagnostics; only the resolved graph sees through `[patch]`, `[replace]`, git, registry and same-name packages, which can otherwise launder a forbidden edge (`cgf-sdk -> shim -> cgf-kernel`). Dev-dependencies are included because the strictest rule is the simplest. | When a crate needs a test-only exception (add an explicit `dev_allow` entry through review) |
| ASM-006 | (Revised 2026-10-17, review of 0a25b26.) In the direct pass a dependency is a workspace edge only if it is a path dependency on the member's own directory; a name match is not enough. Any other path dependency on a non-member is a violation (`NonMemberPathDep`); there is **no** allow-list (the former `RuleSet::allowed_path_deps = ["fake_external"]` was a back door and is removed). Registry and git dependencies count as external in the direct pass and are judged by the resolved pass (ASM-005). In the resolved pass, a non-member package that has the name of a member or of a rule-table crate is a violation (`ImpostorPackage`). Test fixtures model an external dependency as the registry dependency `fake_external = "0.1"` plus `[patch.crates-io] fake_external = { path = "fake_external" }` in the fixture root, so both passes run offline with a committed `Cargo.lock`. | Membership and identity must come from cargo (path, package id), not from names that anyone can choose. The fixture patch is harmless because the resolved pass judges what it resolves to. | Never |
| ASM-007 | The dependency rules are a Rust `const` table in `xtask` (not a config file). It lists every section 4 crate up front, including crates that do not exist yet. | Type-checked, no parser or extra error paths. Future crates are covered on the day they appear. | If non-Rust tooling needs to read the rules |
| ASM-008 | Rule interpretation: `cgf-engine` ("all engine crates") may depend on core, kernel, motion, behavior, templates, plugin-api, plugin-host, net. It may **not** depend on `cgf-sdk`, `cgf-net-dis` or `cgf-net-hla`, because those are plugins loaded dynamically (REQ-SDK-3, no back doors). `cgf-cli` may depend on engine and server. `cgf-api-types` has no workspace deps. | The plainest reading of section 4 together with REQ-SDK-3. | If the human wants DIS linked statically |
| ASM-009 | "`cgf-plugin-api` depends on nothing" means no normal or build dependencies at all, external ones included. `cbindgen` runs from `cargo xtask gen-header`, not from a `build.rs`. | Keeps the ABI crate tiny (section 18 risk 1). | M4, if the plugin-abi-engineer has a strong reason |
| ASM-010 | M0 creates no placeholder crates. The only members are `cgf-core` and `xtask`. The negative tests for `check-deps` use separate fixture workspaces under `xtask/tests/fixtures/`. | The add-crate skill creates each crate in its own milestone. Placeholders would be dead code. | Never |
| ASM-011 | All crates set `publish = false` until a release process exists. | Prevents accidental crates.io publishing. | First release (M9 or earlier, build-engineer) |
| ASM-012 | Lints: the workspace sets `unsafe_code = "deny"` and `missing_docs = "warn"`. Every non-FFI `lib.rs`/`main.rs` also has `#![forbid(unsafe_code)]`. The FFI crates (M4) relax this locally. Clippy: the `pedantic` group is `warn` with a short, commented allow-list (e.g. `module_name_repetitions`, `must_use_candidate`). `unwrap_used`, `expect_used`, `dbg_macro` and `todo` are `warn` and allowed in tests through `clippy.toml` (also `print_*` and `dbg!`, via `allow-print-in-tests` and `allow-dbg-in-tests`). `allow_attributes` and `allow_attributes_without_reason` are `warn`: exceptions use `#[expect(..., reason = "...")]`, so a stale exception fails the build. CI applies `-D warnings`. | NFR-2, NFR-5, "selective `clippy::pedantic`" (section 16). `forbid` cannot be relaxed per crate under workspace lints. | When the allow-list grows (keep it short) |
| ASM-013 | `clippy.toml` sets `disallowed-methods` for `std::time::SystemTime::now`, `Instant::now`, `SystemTime::elapsed`, `Instant::elapsed` and `std::thread::sleep`, and `disallowed-types` for `std::collections::HashMap`, `HashSet` and `RandomState` (both `std::hash` and `std::collections::hash_map` paths), across the workspace. A legitimate site (e.g. the kernel's RealTime clock in M1) uses a local `#[expect(clippy::disallowed_methods, reason = "REQ-K-4: ...")]`. `rand` entries are added in M1 with `SimRng`. Residual gap: a `HashMap` returned by a third-party API and iterated without naming the type is not caught; it stays a review item. | Enforces REQ-K-4 mechanically at no cost, and makes every wall-clock read visible in review. Mutation-checked: `elapsed`, `RandomState::new` and `sleep` each fail clippy. | If it becomes too noisy in server or net crates (give those crates a local `clippy.toml`) |
| ASM-014 | `.gitattributes` normalizes text files to LF (`* text=auto eol=lf`). | Keeps `cargo fmt --check` and future golden files identical on Windows and Linux runners. | Never |
| ASM-015 | Units are hand-written `pub struct X(pub f64)` newtypes in `cgf-core::units`: `Meters`, `Seconds`, `Radians`, `Kilograms`, `MetersPerSecond`, `MetersPerSecondSquared`, `RadiansPerSecond`. Degrees exist only as conversion functions. There is no `uom` crate and no NaN validation inside the types (validation happens at the edges). | REQ-C-4 "newtypes where cheap". These are the quantities M1 `ground.kinematic` needs. | When a quantity is needed that these do not cover |
| ASM-016 | `SimTime` = tick count (`u64`) + `TickRate` (whole hertz, `NonZeroU32`). `dt = 1/hz`. Seconds are computed as `tick / hz`, never by accumulating `dt`. There is no total order across different tick rates. | REQ-C-1: exact integer time, no float drift. Covers A-1's 10-60 Hz. | Before M2 (scenario `tick_rate` field) or M4 (ABI representation), if a fractional Hz is needed |
| ASM-017 | `EntityId` wraps `NonZeroU64`. 0 is never a valid ID, so `Option<EntityId>` costs no space and a future C ABI can use 0 as "none". The kernel (M1) does the allocation (never reused within a run). | REQ-C-2 says u64 only. The niche is free and helps M4. | M4 ABI design (plugin-abi-engineer confirms) |
| ASM-018 | `cgf-core` in M0 has no `serde` derives and no `Clock` trait. Serde comes in M2 (templates). `Clock` belongs to `cgf-kernel` (section 4) in M1. | KISS, no speculative dependencies. | M1 / M2 |
| ASM-019 | The determinism gate (`cargo test -p cgf-engine --test determinism`) is reported as "skipped (from M1)" in M0: no tick pipeline or `cgf-engine` exists yet. | Nothing stateful to hash in M0. | M1 enables it, and it gates every PR from then on |
| ASM-020 | The `deny.toml` license allow-list starts with only the permissive licenses the current dependency tree needs (from MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, Unicode-3.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib; in WI-4 only MIT, Apache-2.0 and Unicode-3.0 are listed, because cargo-deny warns on unused entries). Copyleft is denied. Workspace crates are checked like any other (they carry `MIT OR Apache-2.0`). | ADR 0001. | When a new dependency brings a new license (add it in the PR that adds the dependency, with a note) |
| ASM-021 | The GUI rule REQ-A-4 is not part of `cargo xtask check-deps`. It is enforced by `bun run check:deps` in `gui/` (M8). | The GUI is not a Cargo package. | M8 |

## M0 WI-1 (recorded 2026-10-17 by build-engineer)

| ID | Assumption | Reason | Revisit when |
|---|---|---|---|
| ASM-022 | `[workspace.package] repository` is the placeholder `https://example.invalid/cgf-engine` until a remote exists. The toolchain is pinned to 1.99.1, the locally installed stable, and `rust-version` equals it (ASM-004). | No remote yet (ASM-003). Avoids downloads. | When the remote is created |
| ASM-023 | The pedantic allow-list is `module_name_repetitions`, `must_use_candidate`, `missing_errors_doc`. `print_stdout` and `print_stderr` are `warn` workspace-wide; binaries (`xtask`, `cgf-cli`) will opt out locally. | Keeps the list short (ASM-012). Errors are documented through `thiserror` enums. | When noise or gaps appear |
| ASM-024 | `cargo xtask check-deps` (WI-3) also verifies that every target root (lib, bin, test, example, bench, build script) of every workspace member except `cgf-plugin-api`, `cgf-plugin-host` and `cgf-sdk` has the file-level inner attribute `#![forbid(unsafe_code)]` (a `reason = "..."` is allowed), and that every member manifest sets `lints.workspace = true`. No separate subcommand (KISS). Revised 2026-10-17 (review of 0a25b26): roots are parsed with `syn::parse_file` (`syn` 3, features `full` + `parsing`, xtask only) and manifests with `toml` (`parse` + `serde` + `std`, xtask only), replacing hand-written scanners that strings, raw strings and comments inside attributes could fool. Only `File::attrs` counts, so an attribute inside a comment, a string, an inner module or after an item does not; `cfg_attr(..., forbid(unsafe_code))` is conditional and does **not** count. A root or manifest that does not parse is a violation (`UnparsableSource`); syntax newer than the pinned `syn` would show up the same way (fail closed). Known gaps: doctests and files reached only through `include!` are not scanned. New crates: `syn`, `toml`, `serde_spanned`, `toml_writer` (all MIT OR Apache-2.0; `syn` brings `proc-macro2` and `unicode-ident`, MIT OR Apache-2.0 AND Unicode-3.0, already in the tree); `cargo deny check` passes. | CLAUDE.md rule 5 / NFR-2: `forbid` cannot be set via workspace lints (ASM-012), so a missing attribute would otherwise go unnoticed. Parsers are the simplest way to read Rust and TOML exactly as rustc and cargo do. | If doctests need the guarantee too |
| ASM-025 | ID validation (WI-7): checks run in this order: empty, too long (error carries only a prefix of at most 64 bytes), then a left-to-right scan, then segment count. A character outside `[a-z0-9_.]` is `InvalidChar` even at a segment start (so `Tank.base` is `InvalidChar` at byte 0); only digits and `_` at a segment start are `InvalidSegmentStart`. `EmptySegment.index` is the byte where the empty segment begins (`a..b` -> 2, `a.b.` -> 4, `.a.b` -> 0). Input with an invalid char and a single segment reports `InvalidChar`, not `MissingNamespace`. | ADR 0002 lists the error kinds but not their precedence. Simplest single pass. | When the template loader (M2) needs different diagnostics |
