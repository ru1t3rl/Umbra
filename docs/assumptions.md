# Assumptions

Ambiguities resolved under KISS (spec section 0). Each entry gives its ID, the assumption, the reason, and when to revisit.
Entries that become architectural decisions move to `docs/adr/`.

## M0 Foundations (recorded 2026-10-17 by architect, plan `docs/plans/M0.md`)

| ID | Assumption | Reason | Revisit when |
|---|---|---|---|
| ASM-001 | Library crates live in `crates/<name>/`. Tooling lives in `xtask/`. Reference plugins go in `examples/plugins/` (M4). | Matches the `add-crate` skill. Section 4 names crates but no paths. | Never, unless the workspace layout changes |
| ASM-002 | Repo tooling runs as `cargo xtask <cmd>`. `xtask` is a workspace member binary (aliased in `.cargo/config.toml`) and may use `anyhow`. It may depend on no workspace crate in M0. | The skills already call `cargo xtask`. A Rust tool works the same on Windows and Linux (build-engineer rule). | M4/M5, when `gen-header`/`gen-api` may need workspace crates (the rule change is reviewed) |
| ASM-003 | CI runs on GitHub Actions. No remote is configured yet. | The build-engineer default, and the most common choice. | If the human picks another CI provider |
| ASM-004 | The toolchain is pinned in `rust-toolchain.toml` to the latest stable at the time of WI-1 (with components `rustfmt` and `clippy`). Edition 2024, resolver 3. `rust-version` equals the pinned version. | Reproducible builds (`--locked`). One MSRV to test. | On deliberate toolchain bumps |
| ASM-005 | `check-deps` has two dependency passes. (1) Direct: every declared edge of every kind (normal, build, dev, target-specific, optional, renamed) from `cargo metadata --no-deps` is checked against the allow-list of its crate; a workspace crate missing from the rule table is a violation. (2) Resolved (revised 2026-10-17, review of 0a25b26): `cargo metadata --offline --locked --all-features` (no `--filter-platform`, so all platforms and all optional edges) gives the graph that is actually linked, by package id. For each member, a direct edge to a member must be in its allow-list, and a member reached through non-member packages (members are not expanded) must be in the transitive closure of its allow-list. Because every member-to-member segment is checked by (1) or (2) and the allowed graph is closed and acyclic (rule-table self-test), the transitive guarantee of REQ-A-2/REQ-A-3 now comes from the resolved check, not from the self-test alone. Dev edges are walked from the start member only (cargo resolves dev-dependencies of members only). The resolved pass needs a current `Cargo.lock` and all dependencies in the local cache (`cargo fetch --locked`); otherwise `check-deps` exits 2, it never skips the pass. Cargo runs in the directory of the checked manifest, so `.cargo/config.toml` `[patch]` entries are applied as for a build there. | The direct pass gives precise diagnostics; only the resolved graph sees through `[patch]`, `[replace]`, git, registry and same-name packages, which can otherwise launder a forbidden edge (`umbra-sdk -> shim -> umbra-kernel`). Dev-dependencies are included because the strictest rule is the simplest. | When a crate needs a test-only exception (add an explicit `dev_allow` entry through review) |
| ASM-006 | (Revised 2026-10-17, reviews of 0a25b26 and 341eca7.) In the declared pass a dependency is a workspace edge only if it is a path dependency on the member's own directory; a name match is not enough. Any other path dependency on a non-member is a violation (`NonMemberPathDep`), and a non-path (git or registry) dependency that uses the name of a member or rule-table crate is a violation (`ImpostorDep`). In the resolved pass, every non-member package without a cargo `source` (a local path package, whether it arrived by a path dependency, `[patch]` or `[replace]`) is a violation (`NonMemberPathPackage`), because its code escapes the forbid and lints checks; and a non-member package with the name of a member or rule-table crate is a violation (`ImpostorPackage`). There is **no** allow-list (the former `RuleSet::allowed_path_deps = ["fake_external"]` was a back door and is removed). Test fixtures model an external dependency as the registry dependency `fake_external = "0.1"` served by a vendored directory source (`.cargo/config.toml` `[source.crates-io] replace-with` a `directory = "vendor"` source, `vendor/fake_external/.cargo-checksum.json` = `{"files":{},"package":null}`), so it has a crates.io source and both passes run offline with a committed `Cargo.lock`; the `launder_*` fixtures use `[patch]` on purpose. Residual risk: source replacement (a vendored or mirrored registry) makes any code look like a crates.io package, so `check-deps` cannot see it; cargo-deny does not catch it either (a replaced source keeps the crates.io source id, so `unknown-registry = "deny"` never fires; confirmed by review of 6d8a8a2). Mitigation: the test `xtask/tests/repo_config.rs` (gate 3) fails if the repo's `.cargo/config.toml` has `[source]` or `[patch]`, or the root `Cargo.toml` has `[patch]` or `[replace]`. Config files above the repo root are out of scope. Rule-table names (`umbra-*`) are reserved even before the crate exists, so an outside crate with such a name is always a violation. | Membership and identity must come from cargo (path, package id, source), not from names that anyone can choose. | Never |
| ASM-007 | The dependency rules are a Rust `const` table in `xtask` (not a config file). It lists every section 4 crate up front, including crates that do not exist yet. | Type-checked, no parser or extra error paths. Future crates are covered on the day they appear. | If non-Rust tooling needs to read the rules |
| ASM-008 | Rule interpretation: `umbra-engine` ("all engine crates") may depend on core, kernel, motion, behavior, templates, plugin-api, plugin-host, net. It may **not** depend on `umbra-sdk`, `umbra-net-dis` or `umbra-net-hla`, because those are plugins loaded dynamically (REQ-SDK-3, no back doors). `umbra-cli` may depend on engine and server. `umbra-api-types` has no workspace deps. | The plainest reading of section 4 together with REQ-SDK-3. | If the human wants DIS linked statically |
| ASM-009 | "`umbra-plugin-api` depends on nothing" means no normal or build dependencies at all, external ones included. `cbindgen` runs from `cargo xtask gen-header`, not from a `build.rs`. | Keeps the ABI crate tiny (section 18 risk 1). | M4, if the plugin-abi-engineer has a strong reason |
| ASM-010 | M0 creates no placeholder crates. The only members are `umbra-core` and `xtask`. The negative tests for `check-deps` use separate fixture workspaces under `xtask/tests/fixtures/`. | The add-crate skill creates each crate in its own milestone. Placeholders would be dead code. | Never |
| ASM-011 | All crates set `publish = false` until a release process exists. | Prevents accidental crates.io publishing. | First release (M9 or earlier, build-engineer) |
| ASM-012 | Lints: the workspace sets `unsafe_code = "deny"` and `missing_docs = "warn"`. Every non-FFI `lib.rs`/`main.rs` also has `#![forbid(unsafe_code)]`. The FFI crates (M4) relax this locally. Clippy: the `pedantic` group is `warn` with a short, commented allow-list (e.g. `module_name_repetitions`, `must_use_candidate`). `unwrap_used`, `expect_used`, `dbg_macro` and `todo` are `warn` and allowed in tests through `clippy.toml` (also `print_*` and `dbg!`, via `allow-print-in-tests` and `allow-dbg-in-tests`). `allow_attributes` and `allow_attributes_without_reason` are `warn`: exceptions use `#[expect(..., reason = "...")]`, so a stale exception fails the build. CI applies `-D warnings`. | NFR-2, NFR-5, "selective `clippy::pedantic`" (section 16). `forbid` cannot be relaxed per crate under workspace lints. | When the allow-list grows (keep it short) |
| ASM-013 | `clippy.toml` sets `disallowed-methods` for `std::time::SystemTime::now`, `Instant::now`, `SystemTime::elapsed`, `Instant::elapsed` and `std::thread::sleep`, and `disallowed-types` for `std::collections::HashMap`, `HashSet` and `RandomState` (both `std::hash` and `std::collections::hash_map` paths), across the workspace. A legitimate site (e.g. the kernel's RealTime clock in M1) uses a local `#[expect(clippy::disallowed_methods, reason = "REQ-K-4: ...")]`. `rand` entries are added in M1 with `SimRng`. Residual gap: a `HashMap` returned by a third-party API and iterated without naming the type is not caught; it stays a review item. | Enforces REQ-K-4 mechanically at no cost, and makes every wall-clock read visible in review. Mutation-checked: `elapsed`, `RandomState::new` and `sleep` each fail clippy. | If it becomes too noisy in server or net crates (give those crates a local `clippy.toml`) |
| ASM-014 | `.gitattributes` normalizes text files to LF (`* text=auto eol=lf`). | Keeps `cargo fmt --check` and future golden files identical on Windows and Linux runners. | Never |
| ASM-015 | Units are hand-written `pub struct X(pub f64)` newtypes in `umbra-core::units`: `Meters`, `Seconds`, `Radians`, `Kilograms`, `MetersPerSecond`, `MetersPerSecondSquared`, `RadiansPerSecond`. Degrees exist only as conversion functions. There is no `uom` crate and no NaN validation inside the types (validation happens at the edges). | REQ-C-4 "newtypes where cheap". These are the quantities M1 `ground.kinematic` needs. | When a quantity is needed that these do not cover |
| ASM-016 | `SimTime` = tick count (`u64`) + `TickRate` (whole hertz, `NonZeroU32`). `dt = 1/hz`. Seconds are computed as `tick / hz`, never by accumulating `dt`. There is no total order across different tick rates. | REQ-C-1: exact integer time, no float drift. Covers A-1's 10-60 Hz. Resolved 2026-10-17 (human): whole hertz only; the M2 scenario field `tick_rate_hz` is a positive integer. A fractional form would need a new field form and a `schema_version` bump. Still check at M4 (ABI representation) |
| ASM-017 | `EntityId` wraps `NonZeroU64`. 0 is never a valid ID, so `Option<EntityId>` costs no space and a future C ABI can use 0 as "none". The kernel (M1) does the allocation (never reused within a run). | REQ-C-2 says u64 only. The niche is free and helps M4. | M4 ABI design (plugin-abi-engineer confirms) |
| ASM-018 | `umbra-core` in M0 has no `serde` derives and no `Clock` trait. Serde comes in M2 (templates). `Clock` belongs to `umbra-kernel` (section 4) in M1. | KISS, no speculative dependencies. | M1 / M2 |
| ASM-019 | The determinism gate (`cargo test -p umbra-engine --test determinism`) is reported as "skipped (from M1)" in M0: no tick pipeline or `umbra-engine` exists yet. | Nothing stateful to hash in M0. | M1 enables it, and it gates every PR from then on |
| ASM-020 | The `deny.toml` license allow-list starts with only the permissive licenses the current dependency tree needs (from MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, Unicode-3.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib; in WI-4 only MIT, Apache-2.0 and Unicode-3.0 are listed, because cargo-deny warns on unused entries). Copyleft is denied. Workspace crates are checked like any other (they carry `MIT OR Apache-2.0`). | ADR 0001. Zlib was added in M1 WI-10 for `foldhash` (via `hecs` and `hashbrown`). | When a new dependency brings a new license (add it in the PR that adds the dependency, with a note) |
| ASM-021 | The GUI rule REQ-A-4 is not part of `cargo xtask check-deps`. It is enforced by `bun run check:deps` in `gui/` (M8). | The GUI is not a Cargo package. | M8 |

| ASM-022 | `[workspace.package] repository` is the placeholder `https://example.invalid/umbra` until a remote exists. The toolchain is pinned to 1.99.1, the locally installed stable, and `rust-version` equals it (ASM-004). | No remote yet (ASM-003). Avoids downloads. | When the remote is created |
| ASM-023 | The pedantic allow-list is `module_name_repetitions`, `must_use_candidate`, `missing_errors_doc`. `print_stdout` and `print_stderr` are `warn` workspace-wide; binaries (`xtask`, `umbra-cli`) will opt out locally. | Keeps the list short (ASM-012). Errors are documented through `thiserror` enums. | When noise or gaps appear |
| ASM-024 | `cargo xtask check-deps` (WI-3) also verifies that every target root (lib, bin, test, example, bench, build script) of every workspace member except `umbra-plugin-api`, `umbra-plugin-host` and `umbra-sdk` has the file-level inner attribute `#![forbid(unsafe_code)]` (a `reason = "..."` is allowed), and that every member manifest sets `lints.workspace = true`. No separate subcommand (KISS). Revised 2026-10-17 (review of 0a25b26): roots are parsed with `syn::parse_file` (`syn` 3, features `full` + `parsing`, xtask only) and manifests with `toml` (`parse` + `serde` + `std`, xtask only), replacing hand-written scanners that strings, raw strings and comments inside attributes could fool. Only `File::attrs` counts, so an attribute inside a comment, a string, an inner module or after an item does not; `cfg_attr(..., forbid(unsafe_code))` is conditional and does **not** count. A root or manifest that does not parse is a violation (`UnparsableSource`); syntax newer than the pinned `syn` would show up the same way (fail closed). Known gaps: doctests and files reached only through `include!` are not scanned. New crates: `syn`, `toml`, `serde_spanned`, `toml_writer` (all MIT OR Apache-2.0; `syn` brings `proc-macro2` and `unicode-ident`, MIT OR Apache-2.0 AND Unicode-3.0, already in the tree); `cargo deny check` passes. | CLAUDE.md rule 5 / NFR-2: `forbid` cannot be set via workspace lints (ASM-012), so a missing attribute would otherwise go unnoticed. Parsers are the simplest way to read Rust and TOML exactly as rustc and cargo do. | If doctests need the guarantee too |
| ASM-025 | ID validation (WI-7): checks run in this order: empty, too long (error carries only a prefix of at most 64 bytes), then a left-to-right scan, then segment count. A character outside `[a-z0-9_.]` is `InvalidChar` even at a segment start (so `Tank.base` is `InvalidChar` at byte 0); only digits and `_` at a segment start are `InvalidSegmentStart`. `EmptySegment.index` is the byte where the empty segment begins (`a..b` -> 2, `a.b.` -> 4, `.a.b` -> 0). Input with an invalid char and a single segment reports `InvalidChar`, not `MissingNamespace`. | ADR 0002 lists the error kinds but not their precedence. Simplest single pass. | When the template loader (M2) needs different diagnostics |

| ASM-028 | The hard-coded scenario lives in `umbra_engine::demo`: 3 ground entities near 52°N 4°E on flat terrain at 0 m, square routes of four 500 m legs, arrival radius 5 m, ground params from the spec 7.1 example (18 m/s, 40 deg/s, 2.5 m/s²); cruise speed jittered per entity from the `SCENARIO` RNG stream. M2: replaced by `examples/scenarios/walking_skeleton/` (M2 WI-11, ASM-061) and `umbra_engine::demo` deleted |
| ASM-029 | Route following in M1 is a kernel-internal stand-in system in the Behavior phase (`Route` component; emits `SetSpeed` + `MoveTo` each tick, `Hold` after the last waypoint; advances when within the arrival radius horizontally). A public system-registration seam is designed when its second user (the behavior runtime adapter) exists (KISS). Hold is non-latching: the stand-in re-evaluates every tick, so an entity that drifts out of the final arrival radius is steered back to the last waypoint. | M3: remove the stand-in; route following moves to the behavior runtime (`FollowRoute`/`move_to`) |
| ASM-030 | `Intent` in M1 has only `MoveTo { destination: Ecef }`, `SetSpeed(MetersPerSecond)` and `Hold`, and is `#[non_exhaustive]`. Intents are re-emitted every tick and cleared before the Behavior phase. Resolution in a motion model: `Hold` wins; otherwise the last `MoveTo` and last `SetSpeed` win; no intent means decelerate to a stop; unknown variants are ignored. | REQ-B-2's other variants have no consumer before M3. Stateless models are simpler and deterministic. | M3 (full intent set and versioning) |
| ASM-031 | `MotionModel` (in `umbra-core`): `fn id(&self) -> &MotionModelId; fn step(&self, &KinematicState, &[Intent], Seconds, &dyn TerrainProvider) -> KinematicState`, `Send + Sync`, infallible, no state across ticks. Parameters are bound when the instance is constructed; entities share an instance through `Arc<dyn MotionModel>`. LSP contract checks are plain functions in `umbra_core::motion::contract` returning `Result<(), ContractViolation>`. | REQ-M-1 signature; only built-in implementations exist, so a fallible signature would be speculative. | M7 (motion-model plugin kind may need errors and per-entity params) |
| ASM-032 | `TerrainProvider` in M1 has `height_at` and `surface_normal_at` only; `line_of_sight` is added with perception in M3. `FlatTerrain { height }` is a constant height above the WGS-84 ellipsoid, normal = local up. `ground.kinematic` sets pitch and roll to 0 (it does not tilt to the surface normal in M1). | Terrain following needs only height; LOS semantics (earth curvature) are best decided with its first consumer. | M3 (LOS), or when non-flat terrain arrives (normal alignment) |
| ASM-033 | Coordinate conventions: ECEF in meters (`f64`); geodetic latitude/longitude in radians plus height above the WGS-84 ellipsoid, longitude wrapped to (-π, π], latitude validated in [-π/2, π/2]; ENU and NED tangent at an origin; orientation is a unit quaternion (Hamilton, active) rotating body FRD axes to ECEF; Euler helper = heading/pitch/roll relative to local NED (ZYX), heading clockwise from true north. ECEF to geodetic is closed form (Heikkinen/Zhu 1994), no data-dependent iteration (one fixed correction step allowed), finite for all finite input (radicand clamped at 0 near the polar axis; spherical fallback beyond 1e12 m where the intermediates would overflow). | D-15, REQ-C-3; matches DIS's ECEF-based orientation needs in M6; no iteration count that could vary with input. | M6 (DIS orientation mapping) |
| ASM-034 | `umbra_core::math` wraps every non-exact `f64` function (trig, inverse trig, exp/log, `powi` as a fixed-order product, `powf`, `cbrt`, `hypot`) and `clippy.toml` bans those direct methods, the hyperbolic ones that have no wrapper yet (add one to `math` if needed), and `mul_add` workspace-wide, not just in simulation crates. `math.rs` carries the only `#![expect(clippy::disallowed_methods, reason = "ADR 0003 ...")]`. `sqrt`, `abs`, `floor`, `to_radians`/`to_degrees` and `+ - * /` stay allowed (IEEE-exact). | ADR 0003: one swap point for `libm`. Workspace-wide is simpler than per-crate config and costs nothing outside simulation code. | If cross-OS determinism is required (ADR 0003 option 2) |
| ASM-035 | Wall time is read only through the `WallClock` trait (`now`, `sleep_until`). `StdWallClock` in `umbra-kernel/src/clock/wall.rs` is the only implementation using `Instant`/`thread::sleep`, with one module-level `#![expect(clippy::disallowed_methods, reason = "REQ-K-4: ...")]` in a private `mod real` of that file (its constructor and trait impl both need `Instant`). `ManualWallClock` (public) serves tests and embedding. The `Clock` owns `SimTime` and pacing; systems never see wall time. Real-time/scaled deadlines are computed from integer tick differences since an anchor, re-anchored on resume and mode change; when behind, ticks run back to back (never skipped) and `Clock::behind()` reports the lag of the tick just run: the wall time past that tick's own deadline, when it exceeds one (scaled) period. `set_mode` to the current mode is a no-op; leaving Stepped drops pending steps. `advance` anchors the schedule if no poll did. `TimeScale` is limited to [1e-3, 1e6]. | D-5, REQ-K-3, REQ-K-4, REQ-K-8: a single, reviewable wall-clock site; tests stay fast and deterministic. | M5 (commands may need a blocking wait in Stepped/paused) |
| ASM-036 | Tick semantics: tick `k` runs the phases with `now = SimTime(k)` and `dt`; afterwards the clock is at `k + 1`, and snapshots/hashes are labelled with the post-tick time. In M1 entities are spawned only between ticks (no in-tick spawn or despawn). | Simplest unambiguous rule; spawn/despawn intents come in M3. | M3 |
| ASM-037 | ECS ordering rule: `hecs` handles never leave `umbra-kernel`; `EntityId` (from 1, never reused) maps through a `BTreeMap`. | ASM-038 | `SimRng`, `RngStream` and the canonical `StateHasher` are pure types in `umbra-core`; the kernel owns the instance and the per-entity `EntityRng` component (created at spawn, keyed by `EntityId`, hashed). Scenario-level randomness uses the `SCENARIO` domain keyed by placement index. | Behavior and motion crates may depend only on core, yet must receive RNG streams; the algorithm is pure math (ADR 0006/0007). | M4 (host API exposure) |
| ASM-039 | M1 snapshots are synchronous (`Kernel::snapshot()`, entities sorted by id). The bounded, drop-on-slow observer buffer of REQ-K-6 arrives with `EngineHandle` in M5. | No observer exists before M5. | M5 |

| ASM-044 | Positions are stored only in ECEF (D-15); geodetic is derived on demand for terrain queries and display.
