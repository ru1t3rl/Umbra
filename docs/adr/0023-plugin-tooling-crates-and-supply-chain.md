# ADR 0023: Plugin tooling, crates and supply chain

- **Status**: Accepted (human project owner, 2026-10-18; proposed by the architect in the M4 plan `docs/plans/M4.md`).
  Item 5 was accepted conditionally on a lint test. Amended 2026-10-18 after the ABI design review (approved
  by the human): the test (review R-M5) showed the premise false, so **item 5 is dropped under its own
  condition**: plugin crates keep `#![forbid(unsafe_code)]`; CLAUDE.md rule 5, NFR-2 and ASM-024 are
  unchanged. Items 1-4 are amended in place (marked "(amended: R..)"); summary at the end.
- **Requirement IDs**: REQ-SDK-2, REQ-SDK-3, REQ-P-1, REQ-A-1..3, NFR-2, NFR-3, NFR-4, D-6, D-19, ADR 0001,
  ADR 0004, ASM-002, ASM-005, ASM-009, ASM-020, ASM-024
- **Affected**: root `Cargo.toml`, `deny.toml`, `xtask` (rule table, `gen-header`, `build-plugins`, one
  regression fixture), `docs/build.md`, `umbra-plugin-host`, `umbra-sdk`, plugin crates

## Context
M4 activates gates 11-13 (`docs/build.md`): header drift, plugin build, plugin failure matrix. Loading
needs `dlopen`/`LoadLibraryW`; the header is "generated by `cbindgen`" (REQ-SDK-2, section 4); the
acceptance needs "a C example compiles against the header"; plugin tests need real libraries built from
Rust. Constraints: `cargo deny` allows only MIT, Apache-2.0, Unicode-3.0, Zlib (ASM-020) and denies
copyleft; `cbindgen` is MPL-2.0. `export_plugin!` must emit `#[unsafe(no_mangle)] extern "C" fn
umbra_plugin_entry`. *(amended: R-M5)* The original context assumed that `unsafe_code` then fires in the
plugin crate. The review's test (rustc 1.99.1, edition 2024, `-D warnings`, a `macro_rules!` from another
crate) showed: `#![forbid(unsafe_code)]` plus a macro that emits only `#[unsafe(no_mangle)]` compiles
cleanly; the same macro emitting `#[allow(unsafe_code)]` or `#[expect(unsafe_code)]` is error E0453.

## Options and decision (one row per question; recommended option first)
1. **Library loading**: (a) `libloading` (ISC; tiny, cross-platform) and add `ISC` to `deny.toml` in that
   PR; (b) hand-written `dlopen`/`LoadLibraryW` declarations (no dependency, more `unsafe` and platform
   code). **Chosen: (a).** *(amended: R-M4)* Load flags are explicit: Linux
   `libloading::os::unix::Library::open(path, RTLD_NOW | RTLD_LOCAL)`; Windows
   `libloading::os::windows::Library::load_with_flags(path, LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR |
   LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`; the path is always absolute (`std::path::absolute`, or the canonical
   path with the `\\?\` prefix stripped), never a bare name; the host never calls the process-wide
   `SetDefaultDllDirectories`. The entry symbol is read as a raw pointer and null-checked before it becomes
   a function pointer.
2. **Header generation**: (a) `cbindgen` as an installed tool pinned like cargo-deny
   (`cargo install --locked cbindgen@<pinned>`), run by `cargo xtask gen-header [--check]`, which refuses a
   different `cbindgen --version`; config `crates/umbra-plugin-api/cbindgen.toml`; output committed at
   `crates/umbra-plugin-api/include/umbra_plugin_api.h`. MPL-2.0 never enters `Cargo.lock`; (b) `cbindgen`
   as an `xtask` library dependency with a per-crate MPL-2.0 exception in `deny.toml`. **Chosen: (a)**
   (ASM-009). *(amended: R-M6)* Config: `language = "C"`, C11, `cpp_compat = true`, include guard
   `UMBRA_PLUGIN_API_H`, SPDX header (ADR 0001), `usize_is_size_t = true`; the opaque handle types are
   excluded from export and declared in `after_includes` as incomplete types (`typedef struct
   UmbraBehavior UmbraBehavior;`, `typedef struct UmbraInstance UmbraInstance;`), together with
   `_Static_assert(sizeof(void*) == 8, ..)`, `UMBRA_EXPORT` (`__declspec(dllexport)` on Windows,
   `__attribute__((visibility("default")))` elsewhere) and, in the `trailer` after `UmbraStr`, `UMBRA_STR(lit)`
   and `UMBRA_STR_INIT(lit)` for static initializers (amended 2026-10-18 after the ABI re-review). `gen-header --check` compares
   with line endings normalised to LF (the repo's `.gitattributes` already forces LF, ASM-014).
3. **C example**: (a) `examples/plugins/c-circle/plugin.c` is compiled with `-std=c11 -Wall -Wextra
   -Werror -pedantic` (MSVC `/std:c11 /W4 /WX`; `/std:c11` amended 2026-10-18 after the ABI re-review) into a shared library and loaded by a host test that ticks an
   entity, using the `cc` crate (MIT OR Apache-2.0) as an `umbra-plugin-host` dev-dependency, and packaged
   by `xtask build-plugins` (also `cc`); a C compiler becomes a prerequisite of the local gate; (b) compile
   only. **Chosen: (a).** *(amended: R-M7)* The layout proof does not rely on hand-copied numbers: a host
   test generates, from Rust `offset_of!`/`size_of`, one `_Static_assert(offsetof(T, f) == N)` per field and
   one `_Static_assert(sizeof(T) == N)` per struct, and compiles that file against the header; literal
   64-bit pins stay in `umbra-plugin-api/tests/layout.rs`.
4. **Crates and members**: new crates `umbra-plugin-api` (`no_std`, no dependencies), `umbra-plugin-host`
   (core, plugin-api; `libloading`, `toml`, `serde_json`, `thiserror`, `tracing`), `umbra-sdk`
   (plugin-api; `serde_json`, `thiserror`), all already in the rule table. Also workspace members: the
   example `examples/plugins/wander` (package `example-wander`, explicit member entry) and the test fixture
   `crates/umbra-test-plugin` (a cdylib built with the SDK, not in section 4, recorded here). Rule-table
   entries: both may depend on `umbra-sdk` only (REQ-SDK-3); both carry `#![forbid(unsafe_code)]` like
   every crate outside the three FFI crates. Tests that need a library build it with `cargo build --locked
   --offline -p <pkg> [--features ..] --target-dir <CARGO_TARGET_TMPDIR>/plugins` once per test binary (one
   helper file shared with `#[path]`), so gate 3 stays self-contained. *(amended: R-M8)* Feature variants
   of the fixture all produce the same file name, so after each build the helper copies the library to a
   unique path in its own package directory (`<CARGO_TARGET_TMPDIR>/plugin-packages/<variant>/`) and never
   overwrites a file that may already be loaded.
5. ~~**`unsafe` in SDK-built plugin crates**~~ **Dropped** *(amended: R-M5)*: `export_plugin!` emits no lint
   attribute and exactly one item, `#[unsafe(no_mangle)] pub extern "C" fn umbra_plugin_entry(host: *const
   UmbraHostApi) -> *const UmbraPluginDescriptor { $crate::__private::entry::<..>(host) }`, whose body is
   safe; descriptors, vtables (generic trampolines) and any `unsafe impl Sync` static wrapper live inside
   `umbra-sdk`. Plugin crates keep `#![forbid(unsafe_code)]` (checked by `check-deps` as today). No xtask
   plugin-crate class and no token scan. A regression fixture in `xtask` keeps the lint fact true:
   `forbid(unsafe_code)` plus an external macro that emits `#[unsafe(no_mangle)]` must compile.
   *(Amended 2026-10-19, human decision after the WI-7 review, ADR 0019)* The generated entry is now
   `pub unsafe extern "C" fn` whose body is `unsafe { $crate::__private::entry::<..>(host) }` (`entry` is a
   `pub unsafe fn`); the `unsafe` comes from the external macro, so the conclusion above holds, pinned by
   two more fixtures (the macro shape compiles; the same entry written directly is rejected).

## Consequences
- Easier: offline, scripted gates on both OSes; the header and the C example prove the ABI from C with
  generated asserts; plugin crates are `forbid(unsafe_code)` like everything else, so SDK users need no
  `unsafe` and no rule exception exists.
- Harder: two more prerequisites (`cbindgen`, a C compiler); first test run builds plugin libraries
  (target: under a minute, measured in WI-10); `ISC` joins the licence allow-list.
- Revisit if `cbindgen` output drifts across patch versions (pin tighter), if Windows loading needs flags
  beyond those above, if a future rustc makes the `no_mangle` expansion trip `forbid` (the regression
  fixture fails first), or if `cc` cannot find a compiler on a supported machine.

## Amended 2026-10-18 after the ABI design review (approved by the human)
R-M4: explicit load flags, absolute paths, raw symbol null check; R-M5: item 5 dropped, narrowest macro
expansion, regression fixture, no rule change; R-M6: cbindgen configuration for strict C and MSVC; R-M7:
generated C layout asserts; R-M8: fixture variants copied to unique package directories.
