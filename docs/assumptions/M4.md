| ASM-111 | REQ-SDK-1 in M4 delivers the `Behavior` family of SDK traits (`BehaviorFactory`, `Behavior`, `BehaviorInstance`) and `export_plugin!` only; the SDK `MotionModel`, `Sensor` and `NetworkAdapter` traits arrive with their plugin kinds (M6/M7). `umbra new-plugin` (REQ-SDK-4) waits for M7 (decision 7, accepted); the documented examples under `examples/plugins/` are delivered in M4. | The M4 row names only the behavior kind; a trait without a vtable and host bridge would be untestable. | M6 (network adapter), M7 (other kinds) |

| ASM-114 | Plugin param schemas use the ADR 0009 subset with the ASM-068 limits. | ASM-115 | Gate 4 runs three test targets from M4: `cargo test -p umbra-engine --test determinism --test behavior_determinism --test plugin_determinism --locked`; the M2 and M3 target files stay unchanged. `plugin_determinism` builds `example-wander` through the test build helper (ADR 0023 item 4). | Section 15: determinism with a plugin behavior must gate every change. | Never |

| ASM-116 | (R-M5) Plugin crates (the example, the test fixture, third-party plugins) keep `#![forbid(unsafe_code)]`; ASM-024, CLAUDE.md rule 5 and NFR-2 are unchanged and ADR 0023 item 5 is dropped. `export_plugin!` expands to exactly one item, `#[unsafe(no_mangle)] pub unsafe extern "C" fn umbra_plugin_entry(..)`, an unsafe fn whose `unsafe` block (calling the SDK's `pub unsafe fn __private::entry`) comes from the external macro, and emits no lint attribute (with `forbid`, an inner `allow`/`expect(unsafe_code)` is E0453); plugin crates keep `forbid(unsafe_code)` (amended 2026-10-19, human decision after the WI-7 review: until then the entry was a safe fn with a safe body, which let safe code pass it any pointer). | ASM-117 | (R-M10) ABI 0.0 is provisional until WI-14 passes; WI-3..WI-14 may change the layout without a new ADR if the same PR updates the plan's layout table, `tests/layout.rs`, the header and `docs/plugin-abi-changelog.md`. | ASM-118 | (R-M3) Fault state and `on_plugin_fault` belong to one engine: a `PluginHost` is created per scenario load (and per `validate` run) and attached to at most one engine (`Engine::attach_plugins` refuses a second, `EngineError::PluginHostInUse`); the shared image keeps only a "tainted" flag for logging. A fault during a `tick_batch` call discards the whole batch (every item Failure, no intents); RNG draws made before the fault stay consumed and are part of the state hash. Amended 2026-10-18 after the ABI re-review (RR-m2): the host's factories are bound to it; with `HostMode::Run` they build only inside the build scope of the engine the host is attached to (`instantiate_with_plugins`), so a cloned registry cannot build plugin behaviors for another engine (`EngineError::BehaviorBuild`); `validate` uses a `HostMode::Validation` host (dry runs allowed, instances refuse to tick). Cross-thread contention on an image waits on a blocking lock and never faults (RR-B1). | A run must not depend on what other runs in the process did; the faulting tick's state must be well defined. | If one host must serve several engines (M5 server) |
| ASM-119 | (R-M2) Caps: at most 256 capabilities per plugin; IDs at most 128 bytes (`MAX_ID_LEN`); a param schema at most 1 MiB; metadata at most 64 KiB; at most 64 intents per batch item per call (`UMBRA_MAX_INTENTS_PER_ITEM`, the 65th faults the capability); error messages truncated to 4 KiB at a character boundary, decoded lossily. | Bounded, deterministic cost of untrusted descriptors and calls; the numbers are far above any foreseen plugin. | When a plugin legitimately needs more (a minor-version change of the constants' meaning needs an ADR) |
| ASM-120 | (R-M7) ABI v0 supports 64-bit targets only (x86_64, aarch64; Windows x64 and Linux, macOS best effort), where `extern "C"` equals `extern "system"`; all field widths are 1, 4 or 8 bytes with natural alignment, so the layouts in the M4 plan are identical on these targets. `umbra-plugin-api` asserts `size_of::<usize>() == 8`; the header asserts `sizeof(void*) == 8`. | A-3 names only 64-bit platforms; one layout table to pin and assert. | A 32-bit or other-ABI target is requested |
| ASM-121 | (review minor) Plugin package directory names must be valid UTF-8 (otherwise a `Discovery` error on every OS) and are ordered by their UTF-8 bytes; symlinked package directories and libraries are followed, and identity (duplicates, image table) uses the canonical library path. | OS-independent, deterministic load order (REQ-K-4) without UTF-16 or locale rules. | If users need non-UTF-8 paths |
| ASM-122 | (R-B5) `umbra-plugin-host` keeps one process-wide image table (`Mutex`), keyed by canonical library path before opening and by the `umbra_plugin_entry` address after opening and before calling it; one `LoadedImage` per image per process (one entry call, at most one `init`, one `shutdown` if `init` succeeded), with a leaked process-lifetime `UmbraHostApi` per image. Amended 2026-10-18 after the ABI re-review (RR-M1, RR-M2, RR-M3): the counts are per image *lifecycle*; each key has a state `Loading`/`Live`/`Closing` and a load that meets `Loading` or `Closing` waits on a condvar; after release and `shutdown` a later load starts a new lifecycle (entry called exactly twice, new leaked `UmbraHostApi` and `host_ctx`, `init` again; plugins reset global state in `init`); `keep_loaded` is sticky per image. Tokens are resolved against a **thread-local stack of in-progress plugin calls** (image id + call generation), pushed for every call including `init` and `shutdown`; it is call-scoped (empty whenever no plugin call is running on that thread), not persistent global state. Lock order: image table (never held across plugin code or an image drop), then the blocking per-image call lock, then per-host fault state and `PluginLog` as leaves. The image table is the only persistent process-global mutable state in the engine and is an accepted exception to section 16 "no global mutable state", because the operating system's loader already shares the image process-wide; it never affects simulation results (fault state is per host, ASM-118). | Two loads or two hosts sharing one image would otherwise overwrite the SDK's static host pointer and call `init` twice. | If the out-of-process host (REQ-P-11) replaces in-process loading |
| ASM-123 | (M4 WI-5) `BehaviorInstance::as_any_mut` returns `Option<&mut dyn Any>`, so only `'static` instance types can return `Some`; an instance that borrows non-`'static` data keeps the default `None` and a batch then ticks it through `instance.tick`. A batch that downcasts must fall back the same way for any item it does not recognise (never panic). | `dyn Any` requires `'static`; the fallback keeps the contract total. | If a non-`'static` instance needs batching (a different recognition hook) |
| ASM-124 | (M4 WI-5) `tick_each` is the reference semantics and the only batch helper in `umbra-core`; grouping (`Arc::ptr_eq`, order by first entity id) lives in the kernel (WI-6). `BatchItem` is `#[non_exhaustive]` with public fields and a `Debug` impl that prints the entity id and status only. `PluginFaultPolicy` accepts exactly `abort` and `disable_capability` (case-sensitive, no trimming). | Keeps `umbra-core` additive and free of scheduling logic. | Never |
| ASM-125 | (M4 step 4) Test contracts the plan left open, fixed by the acceptance tests: (a) `Kernel::behavior_scratch_capacity(&self) -> usize` (`#[doc(hidden)]`, sum of the grouped Behavior phase's scratch capacities) is the AT-6 growth probe, because kernel test targets are `forbid(unsafe_code)` and cannot install a counting allocator. (b) The WI-10 fixture plugin `umbra-test-plugin` also provides `test.behavior.draw_speed`, `test.behavior.needs_target` and `test.behavior.cross_param`, and Cargo features `entry_panics`, `init_fails`, `init_panics`, `shutdown_panics` and `bad_schema` (its schema uses `anyOf`, which is outside the ADR 0009 subset; `oneOf` is inside it); a library without the entry symbol and one whose entry symbol is null are built from C with `cc` (the null entry as an absolute symbol of value 0, ELF targets), not as fixture features; the `panic = "abort"` row builds the fixture with `--config profile.dev.panic="abort"` through the one shared build helper (`umbra-engine/tests/plugin_support/mod.rs`, included by the host tests), not a feature (contract in that header and in `umbra-plugin-host/tests/plugin_failures.rs`). (b2) `PluginError::AbiMismatch` gains a `field: String` (`descriptor.abi_version`, `capabilities[i].abi_version`, `capabilities[i].vtable.abi_version`, `plugin.toml abi`; vtable fields amended in M4 WI-9) next to the plan's `origin`, `plugin`, `host`, so tests can pin which struct carried the version; `umbra_sdk::Error` carries a private `UMBRA_ERR_*` code (`Error::params` is `UMBRA_ERR_PARAMS`, `Error::new` is `UMBRA_ERR_INTERNAL`, read with `code()`); `umbra_plugin_host::LogLevel` is `#[non_exhaustive]`. (b3) Descriptor errors name the offending field as `descriptor.<f>`, `capabilities[<i>].<f>` or `capabilities[<i>].vtable.<f>` (amended in M4 WI-9 after the WI-8 review: was `vtable.<f>`; also `capabilities[i].metadata.param_types.<name>`). (c) The WI-13 example scenario has entities `wander-direct`, `wander-graph` (blackboard `speed` 12.0) and `patrol-builtin`. (d) `xtask build-plugins` writes `<cargo target dir>/plugins/<name>/` and honours `CARGO_TARGET_DIR`. (e) `umbra list-plugins --json` is only required to contain plugin id, version, capability id and kind as strings; WI-12 fixes the shape and documents it. (f) Host tests enter the run-mode build scope through a test helper (`support::build_behavior`), which WI-9 backs with the RR-m2 mechanism. (g) `Scenario` gains `plugin_paths` and `on_plugin_fault` as public fields, additive for in-workspace users by the M3 `graphs` precedent (ASM-107 g): only the reader constructs a `Scenario`; `Scenario` is not `#[non_exhaustive]`, so for an external user building it literally the change is formally breaking (no such user exists; crates are unpublished). (h) A plugin with zero capabilities is valid (`capability_count` 0, `capabilities` may be null); it loads, runs `init`/`shutdown` and registers nothing (the WI-8 counter fixture relies on it). | The simplest choices consistent with the plan; each is checked by the WI that implements it. | The owning WI (6, 9, 10, 12, 13) if the contract does not fit |
| ASM-126 | (M4 WI-6) Grouped Behavior phase details: (a) The kernel has no fault or discard hook: a batch writes the `status` of its items and the kernel stores it in `last`; whole-batch discard (ADR 0020) is done by the plugin host inside `tick_batch` (WI-9), which leaves the items at their initial Failure with no intents. (b) The scratch vectors of items hold borrows into the world for one call, so they are stored typed `'static` and always empty, and re-typed with an in-place `collect` of a `filter_map` (`relife` in `world/batch.rs`), which keeps the allocation in current std but is not a documented guarantee; if it ever stops, the unit tests `relife_{rows,pending,items}_keeps_allocation` in `world/batch.rs` (capacity and pointer kept) fail and are the guard, because the probe also sums vectors that are not re-typed (the AT-6 test `no_allocation_growth_after_warm_up` is only a coarse check). (c) Each tick clones one `Arc` per batched entity (a counter increment, no allocation) and finds the group by a linear `Arc::ptr_eq` scan, adequate for a handful of groups. (d) Intents are cleared in the first walk, before the group runs. | Smallest safe-Rust way to hold many entities' `&mut` at once without per-tick allocation (no `unsafe` in the kernel). | M9 profiling (NFR-1); a std change to in-place collect |
| ASM-127 | (M4 WI-7) The SDK stores a **copy** of the host API's minor-0 fields (`host_ctx`, `log`, `rng_next_u64`, `rng_next_f64`), never the `UmbraHostApi*`, so it dereferences no host pointer outside the call that passed it (REQ-P-11). The copy is stored by the first entry call of a lifecycle (none stored: the first ever, or the first after `shutdown`; later entry calls keep it, ADR 0019/RR-M1), replaced by every `init` with its `host` argument (so a lifecycle that ended without `shutdown`, e.g. a failed `init`, is reset there), and cleared after the plugin's `shutdown` returns (which may still log). `umbra_sdk::log` is a no-op without a stored copy; the host's `log` result is ignored. The copy (behind an `RwLock`), the descriptor (`OnceLock`, built on the first entry call, never freed) and the empty contacts scratch buffer of `tick_batch` (a `static Mutex`, not a thread-local, so no TLS destructor runs at `dlclose`; added after the WI-7 review) are the SDK's only global state; one `export_plugin!` per binary, and `__private::entry` for a second plugin type in the same binary returns null (`TypeId` check). | REQ-P-11 and the RR-M1 reload rule with the fewest moving parts; tests share one binary-wide copy safely because the harness's hosts are equivalent. | If the host ever changes host API fields after the entry call |
| ASM-128 | (M4 WI-7) SDK input checks beyond the plan's list: a header passes when the major equals the SDK's, `struct_size` is at least the minor-0 size, a multiple of 8, and at most the SDK's own size when the struct declares a minor the SDK knows (a newer minor may be larger); elements of host-written arrays (`items`, `contacts`) must have exactly the SDK's own `struct_size`, the stride the SDK indexes with (R-B3); null `items`/`statuses`/`route`/`contacts` are allowed only with a zero count; `has_route` and `route_complete` must be 0 or 1 and the route array is checked even when `has_route` is 0 (then ignored); an error, intent or value sink without its callback, a null batch, a null or misaligned out-pointer, and a null instance are `UMBRA_ERR_INVALID_ARGUMENT` (with a message whenever the error sink is usable). The whole batch, every view, contact and string, and every instance handle are checked before the first `tick`. | ADR 0019's reader rule applied literally; one pass of checks keeps "no trait call on malformed input" (R-M2) easy to prove. | ABI minor 1 (the SDK then reads only fields inside `struct_size`) |
| ASM-129 | (M4 WI-7) `tick_batch` fault semantics in the SDK: the first host refusal in an item's tick (an RNG draw, or an intent `push`, even when the behavior ignores the `Err` of `Intents::push`) is recorded; the behavior gets 0 or 0.0 for a refused draw and keeps running to the end of its `tick`; the call then ends with the host's code and a message naming the call and item, without writing that item's status or ticking later items (earlier items keep their statuses; the host discards the batch, ADR 0020). A host without RNG callbacks is `UMBRA_ERR_STATE`. A panic ends the call the same way with `UMBRA_ERR_PANIC`. | The plan says a refused draw faults the whole call; stopping at the first fault keeps draws after it from consuming the streams of later entities. | If the host wants per-item fault reporting |
| ASM-130 | (M4 WI-7) Handles and calls without an error sink: every configured behavior and instance is a `Box<Handle<T>>` with the `TypeId` of a per-capability, per-kind tag at offset 0 (never a zero-sized allocation, so every handle has its own address); every call reads the tag first and refuses a handle of another capability or kind with `UMBRA_ERR_INVALID_ARGUMENT` (a foreign handle given to `destroy_*` is logged and left alone). A panic in a call without an error sink (`halt`, `halt_running`, `output`, `destroy_*`, `shutdown`) is logged through the host `log` at error level as `<call>: plugin panicked: <message>` (the WI-10 failure matrix expects `destroy`/`shutdown` in an error log); `halt`, `halt_running` and `output` also return `UMBRA_ERR_PANIC`. | Turns a host bug that mixes handles into an error code instead of type confusion; keeps every panic message visible. | Never (internal to the SDK) |
| ASM-131 | (M4 WI-7) SDK API details the plan left open: `EntityView` has a private `contacts` field behind `contacts()` (the plan's `/* contacts() */`), so plugins cannot build it literally; `Route` mirrors core `RouteView` through accessors (`len`, `is_empty`, `waypoint`, `waypoints`, `next_index`, `is_complete`); empty force strings are `None`; `export_plugin!`'s `init` is a `fn() -> Result<(), umbra_sdk::Error>` and `shutdown` a `fn()`; the marker type `__UmbraPlugin` is declared inside the generated function, so the macro emits exactly one module item; the hidden API is `__private::{Plugin, Capabilities, entry}`, and `entry` is a `pub unsafe fn` with a `# Safety` section called from the generated entry's `unsafe` block, an unsafe fn whose unsafe block comes from the external macro, so plugin crates keep `forbid(unsafe_code)` (amended 2026-10-19, human decision after the WI-7 review; it was a safe fn before); metadata is empty text when nothing is declared, else JSON with `param_types`/`outputs`/`result` as declared (later duplicates win); `set_input` and `output` are in the vtable iff params or outputs are declared (ADR 0020), `halt_running` always. | The simplest choices consistent with the plan's Design block and ADR 0020. | When a second plugin kind needs the same machinery (M6/M7) |
| ASM-132 | (M4, human decision 2026-10-19 after the WI-7 review) Gate 13 (`umbra-plugin-host/tests/plugin_failures.rs`, the real `umbra-test-plugin` library built with `umbra-sdk`) covers only what a plugin built with the SDK can produce: the load and lifecycle rows, panics in every call (`configure`, `instantiate`, `tick_batch`, `halt`, `halt_running`, `set_input`, `output`, `destroy_*`), `intent_flood`, `bad_intent`, `bad_value`, and the `init` and `shutdown` failures. The rows the safe SDK makes impossible are covered only by the in-process raw-ABI host tests, not by the real-library fixture: `no_status` and `bad_status` (`faults.rs` `status_left_unset_is_a_fault`, `status_out_of_range_is_a_fault`), `bad_index` (`faults.rs` `intent_item_index_at_count_is_a_fault`), configure OK with a null handle (`faults.rs` `configure_ok_with_a_null_handle_is_a_build_error`), `halt_error` (`faults.rs` `halt_returning_an_error_code_is_a_fault`), `output_twice` (`faults.rs` `output_sink_called_twice_is_a_fault`), `stale_token` (`tokens.rs` `stale_token_in_a_later_call_is_a_fault`) and `foreign_rng` (`tokens.rs` `rng_with_another_items_token_draws_that_items_stream`). The fixture has no capability for them and the SDK gets no test hooks to fake them. | The fixture must stay `forbid(unsafe_code)` and SDK-only (REQ-SDK-3); the host's checks for these rows do not depend on how the library was built, and the raw tests reach every misbehavior. | If a non-SDK real-library fixture (for example a C one) is added |
| ASM-133 | (M4 WI-8, coordinator decision) The host uses `libloading` **0.9.0**, the version in the offline cargo cache, instead of the plan's 0.8.x (ADR 0023 item 1): a workspace dependency used only by `umbra-plugin-host`; `ISC` is added to `deny.toml` with a note. It pulls `cfg-if` on Unix and `windows-link` on Windows (both MIT OR Apache-2.0, both already in `Cargo.lock`). Used API: `os::unix::Library::open(Some(path), RTLD_NOW \| RTLD_LOCAL)`, `os::windows::Library::load_with_flags(path, LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR \| LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`, `get::<*mut c_void>` read as a raw address (`as_raw_ptr`, null-checked), `into_raw` to keep a library mapped (`keep_loaded`). Paths are made absolute with `std::path::absolute` and a Windows verbatim prefix (`\\?\C:\`, `\\?\UNC\`) is rewritten to the plain form before loading. | The plan named 0.8.x before 0.9.0 was current; 0.9.0 has the same `os::*` API and is available offline. | A `libloading` advisory or a 0.10 release |
| ASM-134 | (M4 WI-8) Host API details: (a) the host writes `UmbraHostApi` in its own (newest) layout, today minor 0: the plugin's declared minor is known only from the descriptor the entry returns, after the struct was passed. A host of a later minor writes its own larger `struct_size`; plugins of an older minor read their prefix under the ADR 0019 reader rule, so callbacks appended in M7 (ADR 0021) stay invisible to them (amended 2026-10-19 at the WI-16 freeze review; the earlier "keep passing the minor-0 size" wording would have blocked the M7 extension). (b) The two entry calls are not "calls" with a call record: they run before `init`, so a host callback made from inside the entry returns `UMBRA_ERR_STATE` (ADR 0019 "before `init`"). (c) In WI-8 the RNG callbacks always refuse (`UMBRA_ERR_STATE`; `UMBRA_ERR_INVALID_ARGUMENT` for a null or misaligned `out` inside a call): RNG tokens exist only inside a `tick_batch` call, which the bridge adds in WI-9. (d) `log` does not truncate messages (it validates the whole message as UTF-8); only error-sink messages are cut at 4 KiB. A null pointer with a length in the error sink records the placeholder `<invalid error message: null pointer with length N>` without reading. (e) Every host callback returns `UMBRA_ERR_INTERNAL` if host code (for example an embedder's `PluginLog`) panics; the payload is dropped inside a second guard and forgotten if its `Drop` panics. | The simplest choices consistent with ADR 0019/0021 that keep every callback total. | ABI minor 1 (a), WI-9 (c) |
| ASM-135 | (M4 WI-8) Descriptor validation beyond the plan's list: the descriptor pointer must be 8-byte aligned (field `descriptor`); a struct (descriptor, capability, vtable) whose minor is newer than the host's is `AbiMismatch` with that struct's field, like a different major; every capability must have the first one's `struct_size` (the array stride); plugin name and version texts are capped at 4096 bytes each (host-internal, not ABI constants); a `builtin.*` **plugin** id is `ReservedId` like a `builtin.*` capability id; checks run in descriptor order (header, id, reserved, kind, version, schema, metadata, vtable, entry/metadata consistency, schema/metadata consistency, duplicates) and the first failure is reported; vtable fields are named `capabilities[<i>].vtable.<f>` (amended in M4 WI-9 after the WI-8 review: was `vtable.<f>` with the capability in the message). Metadata (ADR 0020): empty text is no metadata; unknown keys, non-object maps, a non-string `result`, port names outside `[a-z][a-z0-9_]*` (`validate_name`) and unknown type names are errors; `set_input` must be present **iff** `param_types` is non-empty and `output` iff `outputs` is (both directions); a literal-typed param absent from the schema's `properties` is binding-only and accepted, one present must have that JSON `type` (or a `type` array containing it), and an `entity`/`position` param present in the schema is an error. The schema's top-level `description` (else empty) becomes the catalog description. | ADR 0019's reader rules applied literally, ADR 0020's "iff" taken as written; caps keep the cost of untrusted text bounded. | ABI minor 1 |
| ASM-136 | (M4 WI-8) Identity, origins and duplicates: `PluginPackage::library` is the canonical path (the image-table key) while the **origin** of a load (in `PluginInfo::origin` and every error) is the package directory as discovered joined with the library file name, so a symlinked alias names its own path. Within one host, checks run in this order: canonical path already held (before opening); after the image is found or created, the manifest's id, version and ABI against the descriptor (`ManifestMismatch`), the plugin id not yet loaded by another image (`Duplicate`), both **before `init`** of a new lifecycle (the entry calls have run); then the same image already held (`Duplicate`). A failed load leaves nothing loaded in the host; a duplicate-id image whose lifecycle it started ends at once (no `init`, no `shutdown`). | Errors must name the second location the user typed; checks before `init` avoid running plugin code for a load that fails. | Never |
| ASM-137 | (M4 WI-8) Lifecycle details: (a) `shutdown` messages go to the `PluginLog` of the host that released the image most recently (each host records its log on every image when it drops, in reverse load order), or the loading host's if none released it. (b) Call generations are per image, advanced under the image's call lock; `host_ctx` generations come from the image table (one per lifecycle); neither is a thread-local or separate global counter. (c) Image-table slots are removed eagerly when a lifecycle ends (in the image's `Drop`, after `shutdown` and the close), which wakes waiting loads; a `Live` slot whose `Weak` no longer upgrades is waited on like `Closing`. (d) `shutdown` still runs if the call lock is poisoned (the lock is recovered for this last call) and is skipped with an error log only on same-thread re-entry.
