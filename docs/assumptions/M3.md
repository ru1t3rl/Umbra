| ASM-070 | Node evaluation order (summary of ADR 0013): Owned entities in `EntityId` order; per entity one depth-first pass from the root every tick, children in array order; `sequence`/`selector` are reactive unless `memory = true`; a previously Running node that is not reached is halted; no node is ticked twice in one tick; `repeat` ticks its child at most once per tick; an FSM takes at most one guard and one completion transition per tick, transitions in file order. Behaviors read contacts computed from pre-tick state. | REQ-B-8 asks for a fixed, documented order; the A-001 example needs reactive composites; bounded work per tick. | If profiling (NFR-1) or M8b users want memory composites by default |
| ASM-071 | Blackboard typing: every key is declared in `[blackboard]` with one of `bool`, `number`, `integer`, `string`, `entity`, `position`; key names `[a-z][a-z0-9_]*`; values start unset; a write of the wrong type or to an undeclared key is refused and the writing leaf returns Failure (cannot happen after validation); `integer` values are `i64`, `number` `f64` (finite only), `position` ECEF. A blackboard is created with its instance and is not cleared by halt. Every interface param is also a read-only key of the same name and type in its graph's blackboard (literal or default value set at instantiation, bound value copied in before each tick, ADR 0014); writes to it are refused (`BlackboardError::ReadOnly`) and it must not be redeclared in `[blackboard]` (`duplicate_name`). Amended 2026-10-17 after WI-3 review: `Blackboard::input` on a declared key that is not an input key is `BlackboardError::NotInput`; declaring a key again (`declare` or `declare_input`) replaces it: its type, its value (cleared to unset) and its read-only flag; in graphs the loader's `duplicate_name` check prevents redeclaration, so this only matters for code-built blackboards. | Load-time checking of bindings (REQ-B-12); simplest closed type set covering targets and positions; read-only inputs keep child writes from reaching the parent (REQ-B-11). | If plugins need list or JSON values on the blackboard |
| ASM-072 | FSM exit naming: exits are declared per FSM node in `exits = { <name> = "success" \| "failure" }`; exit names and state names share one namespace per FSM (a clash is `duplicate_name`); a transition's `to` names a state or an exit; entering an exit returns the mapped status and resets the FSM to `initial`. There are no reserved exit names; an FSM without exits returns Running until halted. Hierarchical FSMs are FSM nodes used as a state's node; the inner FSM's exit status is the state node's result for `on` transitions. | REQ-B-7 "named exits mapped to Success/Failure" with the smallest syntax; hierarchy by composition needs no extra mechanism. | M8b if editors need entry/exit actions |
| ASM-073 | Subgraph nesting depth counts the graphs on the longest `subgraph` chain, the referencing root graph included: a chain of 16 graphs is accepted, 17 is `subgraph_too_deep`, reported at the `ref` of the subgraph node that crosses the limit. | ASM-075 | Graph strictness: a graph is a tree; an unknown node name, a node with two parents (FSM states and guards count as parents), a node cycle, or a node not reachable from `root` is an error. | ASM-076 | Parameter references and input bindings are two distinct reserved forms; a TOML table with exactly one key `param` or exactly one key `key`, whose value is a string, is never a literal. (a) `{ param = "<name>" }` (in `params` of `condition`, `action` and `subgraph` nodes) is a build-time reference to an interface parameter of the same graph. (b) `{ key = "<blackboard key>" }` (only as a value in `subgraph` node `params`) is a run-time input binding to the calling graph's blackboard (ADR 0014); anywhere else, including template `[behavior] params`, it is `invalid_binding`. A param the child uses in a `{ param }` reference cannot be bound (`invalid_binding`, note at the reference). Binding types must be equal (`integer` key may feed a `number` param). Leaf params that name keys are plain strings (`target_key`, `store_as`). Amended 2026-10-17 after the WI-4 review: both forms are recognised by one public classifier, `umbra_core::reserved_form(&ParamValue) -> Option<ReservedForm>` (`Param(&str)` / `Key(&str)`), used by `ParamTemplate` and the graph reader; it is applied to values inside a `params` table, never to the table itself (ASM-089 b); `ParamTemplate::substitute` treats a `Key` form as an error (`SubstituteError::Binding`), never as a literal. Binding types are checked against `Interface::types` (graphs of the load) or `ComponentInfo::param_types` (registered behaviors). For (a): it replaces the whole value. At load, the referenced parameter must exist and its schema `type` must be compatible with the target property's `type` (`integer` satisfies `number`); after substitution at each call site (template `[behavior]`, `subgraph` node; down a subgraph chain each supplied value is checked on its own, so a rule over two passed-through values is checked at load only when both come from one call, otherwise only if the component's own `build` enforces it, at spawn time, unlocated, ASM-106 d) the leaf or subgraph params are validated against their schemas and trial-built, errors located at the call site value with a note at the reference. | Interface params must be able to reach nodes (REQ-B-10) with full static checking and no expression language (REQ-B-15). | If authors need computed values |

| ASM-088 | Subgraph data flow per tick of a `subgraph` node: (1) copy every bound input from the parent key into the child's read-only param key (unset copies as unset); if a required bound param (no `default`) is unset, return Failure without ticking the child and halt it if it was Running; an optional bound param that is unset stays unset (its default is not used); "optional" applies only to literal-capable types (`bool`, `number`, `integer`, `string`): binding-only params (`entity`, `position`) cannot have a `default` (a `default` there is `invalid_value`), so they are always required (amended 2026-10-17 after step 4); (2) tick the child once; (3) copy every bound output port to its parent key, including "unset". | ASM-094 | WI-7 `SetHeading` in `builtin.ground.kinematic` (ADR 0016, ASM-030, ASM-082): (a) a finite `SetHeading` replaces any earlier `MoveTo` as the steering intent and a finite `MoveTo` replaces an earlier `SetHeading` (the last wins); a non-finite heading is ignored like a non-finite destination and does not clear earlier steering.
