# Assumptions: M7

Part of the assumptions log; the index and the rules are in `docs/assumptions.md`.

## M7 More plugin kinds and replay (recorded 2026-10-22 by architect, plan `docs/plans/M7.md`; status Proposed with the plan)

Reserved block ASM-600..ASM-799 (parallel tracks with M8, coordinator decision 2026-10-22). The plan and
ADRs 0050-0057 were accepted by the human on 2026-10-22, with H1-H10 as recommended, so every entry below
stands. Each entry names the
alternatives considered (ground rule 3: recommended, best and most future-proof option).

| ID | Assumption | Reason (alternatives considered) | Revisit when |
|---|---|---|---|
| ASM-600 | `Spawn`/`Despawn` are applied by the engine right after `Kernel::tick` (after the Events phase), before the network publish, the tick's hash and its frame; a bare `Kernel` still applies neither (ADR 0052). | Templates and the plugin build scope live in the engine; frozen M3 kernel tests stay. (In-kernel spawner port: breaks frozen tests; opt-in per scenario: two semantics.) | In-tick application is needed |
| ASM-601 | A spawned entity uses its template's motion model, behavior and sensors, the **spawner's force**, the intent's position and heading, speed 0, no route, no name or group, `Owned`. | A launched or dispatched entity belongs to its parent's side; the intent carries no more. (No force: spawned entities would be neutral to everyone; template force: templates have no force, ADR 0015.) | Intent set v2 adds fields to `Spawn` |
| ASM-602 | Order: all spawns of the tick in (spawner id, emission order), then all despawns in id order; an entity that spawns and despawns itself in one tick still spawns first. | Deterministic and lets a carrier release children as it leaves. (Interleaved per entity: order then depends on ids of unrelated entities.) | Never, unless a use case needs interleaving |
| ASM-603 | Caps: at most 256 applied spawns per tick per engine and 100,000 entities in total; excess spawns are dropped in order, with one warning per tick and a counter. | Bounds runaway recursive spawning deterministically. (No cap: memory blow-up; a fault: a full scenario would abort.) | Larger scenarios (NFR-1, M9) |
| ASM-604 | A `Spawn` naming an unknown template or failing to build is dropped with one warning per template id and a counter; it is not a plugin fault. | The intent is data from any behavior; failing the run for it is disproportionate. (Fault the emitting capability: punishes graphs too, which cannot fault.) | Users want strict mode |
| ASM-605 | Lifecycle intents are derived state and are not recorded; replay reproduces them. | Recording them would duplicate deterministic computation. | Never |
| ASM-606 | `Session` updates its entity directory from the tick report's `EntityCreated`/`EntityRemoved` events of spawns and despawns (template, no name). | One source of truth for lifecycle events. (Spawner writing the directory: couples engine and session.) | The directory moves into the engine |
| ASM-607 | The air model takes its target height only from a `MoveTo` destination's ellipsoidal height (routes through the kernel expansion); `SetHeading`/`SetSpeed` keep the current height; no `SetAltitude` intent (intent set stays v1). | No intent set or ABI change for an acceptance-free feature. (`SetAltitude` now: intent set v2, SDK and host changes.) | Users need altitude changes while heading-steering |
| ASM-608 | Air turn rate is `g * tan(max_bank) / max(v, 1 m/s)` capped by `max_turn_rate`; roll equals the bank used in the step (instantaneous); pitch is the flight-path angle; `Hold` slows to `min_speed`, keeping heading and height. | Standard coordinated-turn kinematics, simple and bounded. (Roll-rate dynamics: beyond kinematic v1, REQ-M-3.) | A roll-rate limit is wanted |
| ASM-609 | The air model never descends below terrain height + `min_altitude_agl_m` (default 0) at its position; below it, it climbs at the max climb rate. | REQ-M-2 altitude limits with terrain from `TerrainProvider`. | Terrain-following profiles are wanted |
| ASM-610 | The sea model pins height to `surface_height_m` (default 0 m above the ellipsoid), ignores terrain and `MoveTo` heights, turns at `v / min_turn_radius_m`, never reverses, pitch and roll 0. | REQ-M-2 "constant surface height". (Geoid height: needs a geoid model.) | Tides, geoid, or land collision |
| ASM-611 | Air and sea share a new private `steer` helper; `builtin.ground.kinematic` is not refactored onto it. | Ground's goldens must stay byte-identical (A-001). (Refactor ground: DRY but risks goldens.) | Ground changes for another reason with a golden migration |
| ASM-612 | The four new ABI kinds are unbatched: motion one call per entity, sensor one per observer and sensor, condition and action one per node tick. | ADR 0020 already planned unbatched leaves; motion at 10,000 entities is about 10,000 calls per tick. (Batched vtables: core and kernel hooks with no measured need.) | Profiling (NFR-1, M9) |
| ASM-613 | The sensor bridge marshals the candidate list per call (O(n) per observer). | Matches the core trait; a per-tick cache is an optimisation. | Profiling |
| ASM-614 | A faulted plugin motion model leaves the entity at its position and orientation with zero velocity, for that tick and later under `disable_capability`. | Deterministic, physically "stopped". (Keep velocity: entity state inconsistent; remove entity: too drastic.) | Users want another fallback |
| ASM-615 | Faulted sensor: no contacts from it; faulted condition: false; faulted action: Failure with its intents of the call discarded. | Mirrors ADR 0020 (whole-call discard, Failure). | Never |
| ASM-616 | Plugin motion output must be finite with a unit quaternion within 1e-9 (the core contract tolerance); otherwise it faults. | The kernel must never hold invalid state. (Renormalise silently: hides plugin bugs.) | Never |
| ASM-617 | The terrain service exists only during motion `step` and sensor `sense` calls, where core passes a `TerrainProvider`. | LSP with built-ins. (Terrain for behaviors too: a new behavior input.) | Behaviors get terrain in core |
| ASM-618 | The blackboard service grants exactly the keys named by a leaf's declared blackboard params, as resolved from its params at configure, with their declared access and type. | Isolation (REQ-B-11) by construction, same as built-in leaves. (Whole-blackboard access: hidden coupling.) | Never |
| ASM-619 | REQ-P-5 "event emit" is served by the `CUSTOM` intent (already ABI 0.0), which becomes `SimEvent::Custom`; no `emit_event` callback. | One event path (DRY). (Callback: second path, and sensors/motion would need kernel event plumbing.) | A kind without intents needs to emit events |
| ASM-620 | The `component` capability kind (REQ-P-4) stays reserved: it has no defined semantics and no M7 deliverable; a terrain plugin kind is not in REQ-P-4 and is not added. | No speculative ABI. | The spec defines component plugins or terrain plugins |
| ASM-621 | Recordings are JSON Lines with keys in a fixed order and no wall-clock values; two recordings of the same inputs are byte-identical. | Reproducible artifacts, diff-able. (Timestamps in the header: break byte identity.) | A provenance timestamp is required |
| ASM-622 | Recording file names are free; the docs recommend `*.umbrarec.jsonl`; `serve --record-dir` names files `session-<n>.umbrarec.jsonl` with a per-process session counter. | Deterministic names. (Wall-time names: non-deterministic.) | Never |
| ASM-623 | File and plugin library digests are FNV-1a 64 over the bytes (integrity against accidental change, not security). | Reuses `umbra_core::hash::fnv1a64`, no dependency. (SHA-256: new dependency.) | Recordings cross trust boundaries |
| ASM-624 | Hash cadence: every `hash_every` ticks (default the tick rate), plus the tick after every command or inbound batch, plus the final tick; tests use `hash_every = 1`. | Hashing every tick costs O(state) per tick (NFR-1). | Hashing becomes cheap or divergence localisation needs more |
| ASM-625 | The recorder is lossless with backpressure: a bounded queue (4096 records) to a writer thread; when full the engine thread waits; a write error marks the recording failed, never stops the simulation, and `run --record` exits 1 after the run. | A lossy recording cannot replay (REQ-K-7); the recorder is part of the engine, not a REQ-K-6 observer. (Drop on overflow: unreplayable; write on the tick thread: blocks on every write.) | Real-time runs are affected in practice |
| ASM-626 | Recorded commands: state-changing `spawn` (full spec and resulting id), `remove`, `set_adapter_enabled`; informational `start`, `pause`, `resume`, `step`, `set_clock`, `stop`; queries never. | Only state-changing commands are inputs; control is kept for fidelity. | New state-changing commands |
| ASM-627 | Network inbound is recorded per adapter per tick as the canonical messages exactly as polled, before the manager processes them; adapter faults are recorded with tick and call. | Echo suppression, type mapping and ghost policy run again on replay, so they are verified too. (Recording ghost updates: skips the manager.) | Never |
| ASM-628 | Replay runs as fast as possible, opens no sockets, discards outbound messages, takes manager settings from the scenario and adapter key spaces from the header (a mismatch is refused). | Re-execution of the real code path (ADR 0054). | Never |
| ASM-629 | Replay refuses on any file-digest or plugin mismatch (exit 2) unless `--allow-mismatch` (then warns and still verifies). | A-2: results need same files and plugins. | Never |
| ASM-630 | `umbra replay` exit codes: 0 ok, 1 divergence or runtime error, 2 input or usage error. | Matches `umbra validate` (REQ-T-6). | Never |
| ASM-631 | A recording without an `end` record is refused unless `--partial`, which replays up to the last record and verifies the hashes it has. | Crash recordings are still useful. | Never |
| ASM-632 | `umbra serve --record-dir <dir>` records every session load to its own file; there is no API to start or stop recordings in M7. | Minimal surface (ADR 0057). | M8 or users ask |
| ASM-633 | The header stores the scenario path as given (canonical absolute) and relative to the recording's directory when possible; replay tries the relative path first, then the absolute one, then `--scenario`. | Recordings stay usable when a repository is moved. | Recordings embed files (open question 3) |
| ASM-634 | State hash v3 is opt-in (`--state-hash 3`, recording header); v2 stays the default and `STATE_HASH_VERSION`/`StateHasher::new()` keep meaning v2; plugin behavior instances are hashed as an opaque tag in v3. | Goldens and frozen tests unchanged (ADR 0055). (Replace v2: every golden moves; keep v2 only: late divergence detection.) | v3 should become the default |
| ASM-635 | New crate `umbra-record` depends on `umbra-core` only among workspace crates (plus `serde`, `serde_json`), `#![forbid(unsafe_code)]`. | SRP, reusable without the engine (ADR 0053). (Module in the engine: mixes format and facade.) | Never |
| ASM-636 | Example plugins: one crate per kind in `examples/plugins/<name>`, workspace members, `umbra-sdk` only, `#![forbid(unsafe_code)]`, `plugin.toml` with `abi = "0.2"` (network example `"0.1"`), packaged by `cargo xtask build-plugins`. | "Third-party style" (REQ-SDK-3, D-41). | Never |
| ASM-637 | The REQ-N-8 recording adapter is the example network plugin `net-jsonl` (record and playback modes, its own encoding, drop-and-count); the lossless replay input is the engine recorder (ADR 0053). | Dogfoods the SDK; no file I/O in the manager crate. (Built-in in `umbra-net`: duplicates the recorder.) | It should ship as a built-in |
| ASM-638 | `umbra new-plugin <kind> <dir>` templates are embedded in the CLI; generated crates depend on the SDK by path (`--sdk-path`) or by version; gate 3 builds one generated kind, the WI evidence builds all six. | Offline builds; gate time bounded. | The SDK is published to a registry |
| ASM-639 | Replay through the control API and recording start/stop endpoints are not in M7; API 1.2.0 adds only `RunStatus.recording`. | No acceptance need; M8 can ask for additive endpoints (1.3.0). | M8 asks |
| ASM-640 | Acceptance evidence on Linux only (as M4-M6); NFR-3 stays unverified. | Human decision 2026-10-19 carried. | Windows runs are available |
| ASM-641 | The frozen ABI test literals edited for ABI 0.2 are rewritten relative to `UMBRA_ABI_VERSION_MINOR` (or derived counts), so later minors need no further edits. | Future-proof; one approval instead of one per minor. (Bump the literals again: same edit every milestone.) | Never |
| ASM-642 | The intent set stays v1 (`INTENT_SET_VERSION = 1`) in M7. | Nothing in M7 needs a new intent. | `SetAltitude` or a richer `Spawn` |
| ASM-643 | Plugin condition and action metadata is `{"blackboard_params": [{"param", "type", "access"}], "result"}`, validated against the schema like behavior metadata (ADR 0020) and mapped to `ComponentInfo` with `Provenance::Plugin`. | Same catalog data as built-in leaves (REQ-B-17). | Never |
| ASM-644 | A spawned entity first acts in the next tick; its RNG stream is keyed by its own id (ADR 0006). | Applied after the tick (ASM-600); per-entity independence. | Never |
| ASM-645 | A despawned entity's behavior instance is dropped during application on the engine thread (plugin `destroy_instance` runs there) and the network link reports `EntityRemoved` in the same tick's publish. | Same path as `Engine::remove` (ADR 0028). | Never |
| ASM-646 | Recording and replay of runs with `on_plugin_fault = abort` end at the faulting tick with `end.reason = "plugin_fault"`; replay reproduces the fault (plugins are deterministic) and verifies the final hash. | Faults are outputs of deterministic code, not inputs. | Plugins with nondeterministic faults (unsupported, ADR 0021) |
