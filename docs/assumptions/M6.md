# Assumptions: M6

Part of the assumptions log; the index and the rules are in `docs/assumptions.md`.

## M6 Networking and DIS (recorded 2026-10-20 by architect, plan `docs/plans/M6.md`; status Proposed with the plan)

Reserved block ASM-224..ASM-299 (parallel tracks). Plan and ADRs 0030-0035 are Proposed; entries change if the human's decisions H1-H10 change them.

| ID | Assumption | Reason | Revisit when |
|---|---|---|---|
| ASM-224 | Network input is applied at the engine tick boundary (same place as M5 commands), right before `Kernel::tick`; network output right after it. The kernel Ingest phase only dead-reckons Remote entities. | Ghost creation needs templates and motion factories that only `umbra-engine` has; keeps the kernel protocol- and registry-free (REQ-A-2, ADR 0030). | A second ingest source needs in-tick application |
| ASM-225 | Adapter entity keys are opaque `u64` (`NetKey`); each adapter packs its protocol identity into them (DIS `site<<32 \| app<<16 \| entity`, RPR the same identifier). | Covers DIS and RPR-FOM; cheap range checks for echo suppression (ADR 0031). | A protocol needs wider keys |
| ASM-226 | The protocol-neutrality source test scans `src/**/*.rs` of `umbra-core`, `umbra-kernel`, `umbra-net`, `umbra-engine` for the case-sensitive words `DIS`, `PDU`, `SISO`, `RPR` and the case-insensitive `1278`, `site_id`, `application_id` (word boundaries). External crate patterns in `check-deps` are anchored (`dis-rs`, `dis`, `open-dis*`, `opendis*`, `*-dis`, `*_dis`, `rti`, `rti-*`, `portico*`, `hla`, `hla-*`) so names such as `redis` do not match. | Enforces the human decision of 2026-10-20 without false positives. | A legitimate crate or word collides |
| ASM-227 | The scenario key is `[[network_adapters]]`; its `name` selects the templates' `network.<name>` table and is the ghosts' `RemoteSource` label (settles ASM-041). | Distinct from the template's `[network.<name>]` tables; one label per adapter instance. | Two instances of one adapter need one template table |
| ASM-228 | `entity_type` is the one key name inside `network.<name>` tables that the manager reads (an opaque token compared for equality); every other key is the adapter's business. | REQ-N-4 default mapping without protocol knowledge; DRY across adapters. | An adapter cannot express its type as one token |
| ASM-229 | Body-frame dead-reckoning models are computed as their world-frame counterparts after rotating the body acceleration into ECEF with the basis orientation. | Exact body-frame integration is not needed for the M6 acceptance; documented approximation. | Interop shows body-frame models in use |
| ASM-230 | A Remote entity's dead-reckoning basis (`RemoteTrack`) is not hashed; the kinematic state it produces is. State hash stays v2. | No golden has Remote entities; the hash covers what the simulation sees. | M7 state hash v3 with replay |
| ASM-231 | Published models in M6: `static`, `velocity` (default), `acceleration`. Rotating and body-frame models are accepted inbound only. | Angular-velocity estimation for publishing adds work with no acceptance need. | A peer needs rotating models from us |
| ASM-232 | Entity type to template mapping is exact token equality; with several templates declaring one token the smallest template id wins with a load warning; no wildcards. | KISS; deterministic. | Users need hierarchical or wildcard matching |
| ASM-233 | Ghost timeouts, heartbeats and thresholds use simulation time (default timeout 12 s, heartbeat 5 s). | Determinism (REQ-K-4); same behavior in every clock mode. | A wall-clock timeout is wanted in real-time mode |
| ASM-234 | Ghosts jump to each received state; no smoothing. | Simulation semantics stay exact; smoothing is a display concern. | GUI display needs it |
| ASM-235 | Inbound run-control messages (DIS Start/Resume, Stop/Freeze) are decoded, counted and ignored. | Acting on them is a control-policy and security question outside M6. | M7 or M9, if remote control is wanted |
| ASM-236 | An inbound entity whose type maps to no template and with no `default_template` is not mirrored; counted as `unmapped`, warned once per token. | A ghost needs a template (motion model identity); no hidden built-in stand-in. | Users want untyped ghosts |
| ASM-237 | DIS timestamps are relative timestamps derived from the batch tick and rate; no absolute (wall-clock) timestamps. | No wall clock in the adapter path; goldens reproducible. | Interop needs absolute time |
| ASM-238 | The file recording adapter (REQ-N-8 SHOULD) is deferred to M7; the loopback hub's capture list serves debugging in M6. | M7 brings recording and replay; one recording design. | M7 |
| ASM-239 | Every Owned entity is published on every enabled adapter; an entity whose template has no `entity_type` for that adapter is published with no type (DIS writes a zero entity type). | REQ-N-2 selection kept minimal; no per-entity filter until asked. | Users need publish filters |
| ASM-240 | While the clock is paused (no ticks) adapters are neither polled nor published to; their queues drop and count. | Ingest and publish are tied to ticks (ADR 0030); peers' ghosts of us time out. | A heartbeat while paused is wanted |
| ASM-241 | A ghost's motion model is its mapped template's motion model, built once per template at load and never stepped (identity in snapshots and the hash only). | `EntityInit` needs one; no new built-in model in the registry. | Ghosts need their own model |
| ASM-242 | Ghosts get the force and name from the message, no behavior and no sensors; Owned sensors perceive them. | D-16; perception of remote entities is the point of mirroring. | Remote sensors are wanted |
| ASM-243 | Inbound `Fire` becomes `SimEvent::Fire` only if shooter and target both map and the weapon id is valid; otherwise counted and dropped. `Detonation` keeps whatever maps. | `SimEvent::Fire` has non-optional ids (ADR 0028). | Fire events with unknown targets are wanted |
| ASM-244 | Run-control actions are published only when `[publish] control = true` (default false). | Unprompted DIS Start/Stop PDUs can disturb other simulations. | Users expect control PDUs by default |
| ASM-245 | The SDK's descriptor declares the lowest minor that defines its exported kinds (behavior 0, network adapter 1). | Keeps M4 plugins and tests at 0.0 (ADR 0033, decision H1). | M7 kinds (0.2) |
| ASM-246 | UDP tests pick ports by binding port 0 on `127.0.0.1`, reading the port and closing the socket before the engines bind; the small race is accepted. | No fixed ports in tests; works in parallel test runs. | Flakes are observed |
| ASM-247 | Broadcast and multicast tests run on Linux loopback with the interface set to `127.0.0.1` (broadcast to `127.255.255.255`, multicast group `239.255.x.y` with loop on); a missing route is a test failure with a clear message. | Acceptance on Linux only (human decision 2026-10-19); no `#[ignore]`. | Another OS is tested |
| ASM-248 | Ghost creation and removal and inbound fire/detonation events are prepended to the tick report's events, before the kernel's events of that tick. | One event list per tick, in a fixed order. | A consumer needs them separated |
| ASM-249 | The DIS decoder accepts v6 and v7 regardless of config; `version` selects the version sent. | Mixed exercises interoperate; the version strategy stays in one place. | Strict version filtering is wanted |
| ASM-250 | `umbra run` prints one `info: net <name>: ...` counter line per adapter to stderr at the end when `--log-level` is `info` or more verbose; stdout is unchanged. | Evidence for the two-process acceptance without changing stdout (golden comparisons). | `--json` output for runs |
| ASM-251 | `umbra validate` configures every adapter (a dry run, no I/O) and never starts it. | Catches config and template-table errors without opening sockets. | Validation should check port availability |
| ASM-252 | A network adapter fault under `disable_capability` disables that adapter in the manager (only `stop` and `destroy` still called); under `abort` the run ends after the tick. | Same policy as behaviors (ADR 0021). | Per-adapter fault policy is wanted |
| ASM-253 | The kernel offers `owned_views(&mut Vec<OwnedView>)` (id, state, force) for publishing instead of a full snapshot. | Avoids cloning intents and contacts every tick (NFR-1). | M9 profiling |
| ASM-254 | Adapters are started when the scenario is instantiated (run or session load) and stopped when the run ends or the session drops, before the plugin host releases its images. | Lifecycle REQ-P-8; no plugin thread outlives its image. | Adapters need start/stop with the run state |
| ASM-255 | Protocol-neutrality scanner details (WI-1): words are delimited by non-ASCII-alphanumerics, so `_` delimits (`remote_site_id`, `DIS_MODE` match); the acronyms also match with a trailing `s` (`PDUs`); code and comments are scanned. Superseded in part by ASM-259 (camel-case humps). The scanner lives in `crates/umbra-net/tests/protocol_neutral.rs` and its list of crates is a copy of `xtask::deps::PROTOCOL_NEUTRAL`. | Catches the realistic spellings; no regex dependency. | A leak with another spelling is found |
| ASM-256 | The external-protocol rule is a separate constant `PROTOCOL_NEUTRAL` (crates `umbra-core`, `umbra-engine`, `umbra-kernel`, `umbra-net`) plus `is_protocol_crate(name)` in `xtask/src/deps/rules.rs`, not a new `CrateRule` field (the frozen `check_rules.rs` builds `CrateRule` by struct literal). It applies to every dependency kind and target, to the neutral crates and to every workspace crate they may depend on (`protocol_scope`: the transitive closure of their allowed workspace dependencies, so `umbra-engine -> umbra-templates -> dis-rs` is reported at `umbra-templates`), in the declared pass (non-workspace edges only; workspace edges to adapters stay `ForbiddenWorkspaceDep`, so no line is doubled) and in the resolved pass (a protocol package reached through non-member packages; `IndirectProtocolDep`, rule label `ADR 0030`). `-` and `_` and case are folded. | Additive to the tests and the table; one line per violation. | `CrateRule` may grow a field |
| ASM-257 | The name patterns add the suffix `-hla` to ASM-226's list, symmetric to `-dis` (so `umbra-net-hla` and `foo-hla` match); the pattern list is: exact `dis-rs`, `dis`, `rti`, `hla`; prefix `open-dis`, `opendis`, `portico`, `rti-`, `hla-`; suffix `-dis`, `-hla`; added after review: prefix `dis-` and infix `-dis-` (no collision with `distance`, `disk`). | Symmetry; HLA adapters are protocol crates too. | A legitimate crate collides |
| ASM-258 | `umbra-net` is a scaffold in WI-1: no `umbra-core` dependency yet (WI-3 adds it), only `NAME`. `socket2 = "0.6.5"` is added to `[workspace.dependencies]` without features and used by no crate until WI-15 (already in `Cargo.lock` through `tokio`, no fetch). | Nothing to depend on yet; avoids an unused dependency. | WI-3, WI-15 |
| ASM-259 | Amends ASM-226 and ASM-255: the source scanner splits identifiers and words into humps (at non-alphanumerics including `_`, at lower-to-upper changes and at the end of an upper-case run; `PDUs` stays whole) and matches the humps `dis`, `pdu`, `siso`, `rpr` (also plural, ignoring case and trailing digits) and the hump pairs `site id`, `application id`; `1278` matches as a token. So `pdu_len`, `PduHeader`, `DisMode` match; `Display`, `dispatch`, `distance`, `DISCARD` do not. It also scans `build.rs` and the `[features]` keys of each neutral crate's `Cargo.toml` (dependency names are `check-deps`' job). A crate without `src` or without a source file fails the test. The crate list is tied to `PROTOCOL_NEUTRAL` by `scanner_crate_list_matches_protocol_neutral` in `xtask/tests/check_rules.rs`. | Real Rust spellings are caught; look-alikes stay clean; no vacuous pass. | A leak with another spelling is found |
| ASM-260 | When `|sin pitch| >= 1 - 1e-15` (within about 4.5e-8 rad of +-90 degrees) `Quaternion::to_world_euler` returns roll 0 and puts the combined rotation into yaw (`yaw = yaw0 - roll0` at +90, `yaw0 + roll0` at -90). The rebuilt rotation differs from the input by at most about 4.5e-8 rad (the discarded roll component, cos pitch); outside that band yaw and roll are recovered normally (ill-conditioned by about 1e-16 / cos pitch, i.e. below 1e-8 rad). | A gimbal lock has no unique decomposition; a fixed rule keeps the output deterministic and finite. | An adapter peer needs another convention |
| ASM-261 | `extrapolate` returns the basis state unchanged for `Static` (including its velocity), for an `elapsed` that is zero, negative or non-finite, and when the extrapolated result would contain a non-finite component. The orientation is renormalized after every rotating step, including a zero turn. A non-finite basis is returned as given: validating inbound values belongs to the adapter decode WI. | Keeps `extrapolate(b, 0) == b` for every model and stops NaN/infinity from being produced by extrapolation. | A static ghost with a velocity should report zero velocity |
| ASM-262 | `SimEvent::Detonation { shooter: Option<EntityId>, target: Option<EntityId>, position: Ecef }`: the engine maps a network `Detonation` (keys) to local entities in WI-17 or the ingest WI; an unmapped key becomes `None`. The `umbra-server` event mapping already ends in a wildcard arm, so `Detonation` is skipped there (empty DTO fields, kind `detonation`) until WI-17 maps it. | The plan names no fields; mirrors `NetMessage::Detonation` with local ids. | WI-17 needs a different payload |
| ASM-263 | `NetEntityType` is an unvalidated `Arc<str>` token (`new`, `as_str`); `NetKey` is `Ord` (map key). The adapter contract suite is the exported macro `umbra_core::network_adapter_contract_tests!($make_config)` over the check functions `net::contract::{check_start_once, check_after_stop, check_poll_max}`; the plain form checks `poll` only loosely (at most `max`, keeps existing items) because it has no inbound traffic; the form `(config, feed = f)` (`f: Fn(&mut dyn NetworkAdapter, &[NetMessage])` delivers three messages) checks `max` exactly. WI-7, WI-11 and WI-15 MUST use the feed arm. The macro takes a concrete config or an `Arc<dyn NetworkAdapterConfig>`; its test names are fixed, so each call needs its own `mod`. A stub with a queue and a deliberately broken adapter test it in `tests/net_model.rs`. | Keeps the suite usable by any adapter, loopback and DIS alike. | An adapter needs inbound traffic in the suite |
| ASM-264 | `umbra-net` gets no `umbra-core` dependency in WI-3 (amends ASM-258): nothing in WI-3 uses it; the first WI that does adds it. | No unused dependency. | WI-4 |
| ASM-265 | The wire kind `network_adapter` (`api::ComponentKind::NetworkAdapter`) and `API_VERSION` 1.1.0 land in WI-3 by human decision 2026-10-21, because `GET /components` lists every registry kind and the engine kind exists from WI-3. WI-17 keeps 1.1.0 (same unreleased milestone). | Additive enum value, a minor bump (ADR 0026). | WI-17 needs more than the one bump |
| ASM-266 | `scripts/m2-compat.sh` check 2b gets the narrowest allowlist, for the H4 edit only: in `crates/umbra-core/src/registry.rs`, the removed line `        const COUNT: usize = 6;` and the added lines `        const COUNT: usize = 7;` and `            ComponentKind::NetworkAdapter => 6,`, matched as exact diff lines, each usable once. Any other changed or added inline-test line (also in the same test), a second copy of the arm, or the arm in another file still fails. `--self-test` covers: H4 alone passes, H4 plus an extra line fails, H4 arm twice fails, H4 arm in another file fails. The self-test also now picks its fixture mutation from `fixtures/dirs/` (an M2-era fixture); `head -n 1` had picked the M5 file `config/empty.toml`, which is out of scope. | Human decision H4 approved the edit (same precedent as ADR 0011), but check 2b had no allowlist, so it failed. | Another approved edit of an M2 inline test needs its own entry |
| ASM-267 | Kernel time rule for remote bases (step 4, WI-4): a basis given to `spawn_remote` or `update_remote` between ticks is taken at the kernel's current time `T`; Ingest dead-reckons every Remote entity with `extrapolate(basis, now - T)`, so the tick running at `T + k` ticks leaves the entity at `extrapolate(basis, k / hz)` and the tick at `T` shows the basis exactly. Chosen over timestamping the basis with the sender's time: a sender time needs a shared clock, which no adapter guarantees, and adds a field to `RemoteState` that every codec would have to fill. Alternatives: sender-timestamped bases (needs clock sync), extrapolating from the tick after `T` (shows the basis one tick late). | Deterministic from simulation time alone (REQ-K-4); a lag of one tick between publisher and receiver is inside the error bound the tests use. | Time synchronisation across engines (M9) |
| ASM-268 | `OwnedView` is defined in `umbra_core::net` and re-exported by `umbra-kernel` (`umbra_kernel::OwnedView`); the plan put it in the kernel, but `NetworkManager::publish` takes it and `umbra-net` may depend on `umbra-core` only. Alternatives: `umbra-net` defines its own view and the engine copies every owned entity every tick (an extra pass and allocation at 10 000 entities, NFR-1); `umbra-net` depends on `umbra-kernel` (breaks the rule table, xtask). The re-export keeps the plan's kernel path valid. | One type, no per-tick copy, no new dependency edge. | A kernel-private field set for publishing |
| ASM-269 | Step 4 interfaces the plan left open: (a) `umbra_net::PublishTracker` (`new(PublishPolicy)`, `evaluate(now, id, &KinematicState) -> Option<RemoteState>` once per tick per owned entity, `removed(id) -> bool`) is the unit-level interface of the publish policy; the manager owns one per adapter. A tracker, rather than free functions over a state struct, because the acceleration estimate and the last-sent basis are per-entity memory. (b) The acceleration published under `acceleration` is the two-tick finite difference `(v_n - v_(n-2)) / (2 dt)`, zero while fewer than three ticks of history exist (smoother than a one-tick difference; the tests use constant acceleration, which both give). (c) A ghost is removed at the first ingest whose time is strictly more than `timeout` after its last update (equal keeps it). (d) The heartbeat is due after `ceil(heartbeat * hz)` ticks. | The plan names settings only; the receiver bound and heartbeat are tested through these. | A rotating or body-frame published model (ASM-231) |
