# Assumptions: M8

Part of the assumptions log; the index and the rules are in `docs/assumptions.md`.

## M8 Full GUI and Windows app (recorded 2026-10-22 by frontend-architect, plan `docs/plans/M8.md`; reserved block ASM-800..ASM-999, ADR 0047)

Proposed with the plan and accepted with it by the human on 2026-10-22 (H-1..H-10 as recommended). Rows are amended in place during the work items; the "Revisit when" column names a concrete trigger or "Never".

| ID | Assumption | Reason | Revisit when |
|---|---|---|---|
| ASM-800 | M8 runs on branch `m8` (worktree `Umbra-m8`) alongside M7; work items tagged M7-dependent (WI-24..WI-27) start only after the named M7 output is merged to `develop` and `gen:api` has run; acceptance and the `m8-done` tag follow `m7-done`. Numbering: ASM-800..ASM-999, ADR 0070..0089, D-80..D-95. | ADR 0047 (human decision 2026-10-22) | Never |
| ASM-801 | The selected entity is plain lifted state (`number \| null`) in the dashboard shell, passed to map-view, entity-inspector as props; selection does not survive page navigation and is not in the URL. | Layering: domain features never import each other; shells only wire (ADR 0078) | Selection must be shared across pages or deep-linked |
| ASM-802 | The selected entity's name label is one absolutely positioned DOM element moved once per animation frame by map-view; no MapLibre text and no glyphs (ASM-314 stays). | One DOM node is not per-entity rendering; glyph PBFs would be a network or asset decision | Labels for many entities are wanted |
| ASM-803 | A map click selects the nearest rendered entity within a 12 px box (`queryRenderedFeatures`); a click on empty map or Escape on the focused map clears the selection. | Touch-size target on a 1.5 px stroked symbol; standard map behaviour | User feedback; symbol size changes |
| ASM-804 | The entity list rebuilds its row model at most every 250 ms (4 Hz); the inspector updates every flushed frame. | Text that changes 30 times a second is unreadable; bounded work at 10,000 entities | Measurement shows headroom or lag |

| ASM-806 | The inspector's REST detail (`getEntity`: motion model, contacts) is refetched every 1 s while running and after each control frame (`cause: control`), not per frame. | Contacts change slowly relative to the UI; REST per frame would load the server | The stream carries detail fields |
| ASM-807 | Contacts are shown by name resolved from the latest frame, `#id` when the entity has no name or is outside the frame; each contact is a button that selects it. | Names are what users recognise; ids are stable | Never |
| ASM-808 | Stop, Unload and Remove entity have no confirmation dialog in M8: they are `danger`-variant buttons kept apart from the one filled azure button; errors show inline. | Vantage has no Dialog component; a new component needs an ADR; actions are reversible by reloading the scenario | User feedback; a Dialog ADR (0079+) |
| ASM-809 | Run-control buttons are enabled from a pure table `availableCommands(run)` that mirrors `docs/api.md` "Commands and states"; the server stays authoritative (a 409 shows its `detail`). | ASM-810 | Step offers presets 1, 10, 100, 1000 ticks and a numeric field (1..1,000,000), only for a stepped clock while running; the step button stays disabled while `step_pending`. | Contract range (`StepRequest.count`); `step_in_progress` otherwise | Never |
| ASM-811 | Clock control: mode chips afap, realtime, stepped, scaled; the scale Slider is logarithmic over 0.1x..100x, and a numeric field accepts the full contract range 0.001..1,000,000. | Common scales reachable by slider; contract range still available | Users need finer slider ranges |
| ASM-812 | Scenarios are loaded by a path relative to the server's scenario root, typed or picked from the last 10 used paths (settings); the four example paths are offered as suggestions; optional clock and seed overrides. No file browser until contract gap G-2. | The contract has no scenario listing; confinement rules apply server-side | G-2 is merged |
| ASM-813 | Problem diagnostics are listed in server order as `file:line:column`, code, message, a severity Badge (`error` when absent, per API 1.1.0) and notes; scenario warnings from a successful load show in a dismissible Alert. | `Diagnostic` shape; "a client that does not know the field reads error" | Never |
| ASM-814 | `DiagnosticList` lives in `@umbra/scenario-control` in M8; M8b moves it into a foundation package if the behavior editor needs it. | No second user in M8 (YAGNI); the move is cheap | M8b planning |
| ASM-815 | The template browser needs a loaded scenario (templates are "of the loaded scenario"); idle shows an empty state with a link to the dashboard. | Contract semantics | Templates become browsable without a scenario |
| ASM-816 | The schema of each `ComponentRef` (motion, sensors, behavior) comes from joining `GET /components` by id; a component or schema not found renders its params as read-only JSON. | `TemplateDetail` carries values, `ComponentEntry` carries schemas; one cached query per session | The contract adds schemas to templates |
| ASM-817 | Parameter forms are read-only in M8 (no template-edit endpoint; REQ-X-12 is M8b). Tests use real API responses captured from a running engine as fixtures (`scripts/capture-fixtures.ts`), which are contract data, not engine source. | REQ-A-4; realistic schemas without importing `crates/` | M8b editing |
| ASM-818 | Units come from the key suffix as the schemas state: `_m` m, `_mps` m/s, `_mps2` m/s², `_deg` °, `_dps` °/s, `_s` s, `_hz` Hz; any other suffix has no unit. | "Units are given by key suffix" (built-in schema descriptions) | A schema carries an explicit unit keyword |
| ASM-819 | `@umbra/schema-form` supports the subset in ADR 0070; any other construct renders as read-only mono JSON with the note "Shown as JSON"; the component never throws (property-tested). | Forward compatible with plugin and M7 schemas | WI-26 or M8b need more |
| ASM-820 | Spawning from the template browser uses `SpawnRequest` only (template, position, heading, speed, name, force, group); no parameter overrides. | The contract has no override field | The contract adds overrides |
| ASM-821 | Plugin status reads `getPlugins`, `RunStatus.fault`/`network_fault`, `listNetworkAdapters` and `listComponents`; it refetches on session and run-state change and polls adapters every 2 s while running. | Counters only grow during a session; faults appear on state changes | The stream carries adapter counters |
| ASM-822 | Component kinds get labels from a table over `ComponentKind`; an unknown kind or provenance renders verbatim. | Forward compatible with M7 (ADR 0047) | WI-25 |
| ASM-823 | The adapter Toggle calls enable or disable; it is disabled for a faulted adapter, with the fault reason shown. | `adapter_faulted` problem; a faulted adapter stays faulted for the session | The contract allows re-enabling |
| ASM-824 | The event journal holds 5,000 records by default (setting 1,000..50,000); events of every decoded frame are appended before coalescing; `events_truncated` and `dropped > 0` add one loss record each; connection, session and run-state changes are records too; notifications at most once per animation frame. | No client-side event loss (ADR 0071); bounded memory | Memory or G-1 |
| ASM-825 | `JournalRecord` is `{ seq, source, level, kind, message, tick?, time_s?, session?, entity_id?, detail?, received_at }`; unknown kinds stay verbatim; ordering is by `seq` (arrival). | One record type for all sources | G-1 adds engine log fields |
| ASM-826 | The log view shows the newest record at the bottom and follows the end until the user scrolls up; filters by source, level and text; "Download" saves the filtered records as JSON Lines client-side. | Common log-viewer behaviour; no server export exists | User feedback |
| ASM-827 | In desktop managed mode the engine's stdout and stderr are captured line by line (ring of 2,000 in Rust); the level is parsed from the tracing default format when recognised, otherwise `info`. | The only engine log source without G-1 | G-1 is merged |
