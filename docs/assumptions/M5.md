| ASM-169 | (M5 WI-3.) Config reader details. (a) The schema file lives with the other file schemas in `crates/umbra-templates/schemas/config.v1.schema.json` (the plan and ADR 0029 say `schemas/config.v1.schema.json`; the repository has no top-level `schemas/`), exported as `umbra_templates::CONFIG_FILE_SCHEMA` and printed by `umbra schema config`. (b) `schema_version` is optional; when present it is checked by a config-local copy of the template check (same codes and messages) against `umbra_templates::config::CONFIG_SCHEMA_VERSION = 1`, independent of the template/scenario `SCHEMA_VERSION` (`< 1` is `invalid_value`, a string is `wrong_type`, newer is `unsupported_schema_version` and nothing else is read). (c) `default_rate_hz <= max_rate_hz` is checked on the effective values, so `max_rate_hz = 20` alone fails against the default of 30; the error points at the key the file sets (the default key if both are set). (d) `allowed_origins` entries are `scheme://host[:port]`: lower-case scheme, non-empty host (a bracketed IPv6 literal is allowed), optional numeric port up to 65535, no path, query, fragment or user info; the host is lower case (upper case is `invalid_value`); the port is ASCII digits only; text in brackets must parse as an IPv6 address. `allowed_hosts` entries are only checked to be non-empty with no whitespace or `/` (ADR 0029 requires no more). (e) `[plugins] paths` entries must be non-empty. (f) Relative `[plugins] paths` and `[server] scenario_root` join the directory of the file as given, so `./umbra.toml` yields `./plugins`. (g) `--config` is a global flag (accepted before or after the command); `schema` uses no setting but still fails (exit 1) on a missing or invalid named file. `--log-level` of `run` loses its clap default so the file can supply it (flag > file > `warn`). `[log] level` applies to `run` only, the one command with logging. The `info: using configuration FILE` line is written by `run` at `--log-level info` or more verbose, and only for a file named with `--config` (an implicit file gets the `note:` only); `validate` and `list-plugins` have no logging and write only the implicit-file `note:`. (h) The reader returns `Config` (`#[non_exhaustive]`, plain values: `Option` for keys without a built-in value, concrete defaults for `[server]`); `umbra-engine` re-exports `Config`, `ConfigError`, `LogLevel`, `ServerConfig`, `StreamConfig`, `load_config`. | Keeps `umbra-templates` free of server types and keeps the reader in the one located pipeline; the smallest rules consistent with ADR 0029. | WI-17 (serve consumes `ServerConfig`; `max_connections` and `allowed_hosts` semantics) |
