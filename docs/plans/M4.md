## Goal
Native plugins drive entities. A plugin is a dynamic library built with `umbra-sdk` (Rust) or against the
generated `umbra_plugin_api.h` (C), exporting only `umbra_plugin_entry`. The host loads it from plugin
directories, checks `plugin.toml` and the ABI version before and after opening it, validates the
descriptor, and registers each `behavior` capability in the one registry (D-8) with `Provenance::Plugin`.
From then on a plugin behavior is used exactly like a registered behavior: as a template `[behavior] ref`
and as a `subgraph` target with bound inputs and outputs. Top-level plugin behaviors are ticked in
batches (REQ-B-4), with time passed in the call and randomness only from the entity's hashed stream via
the host API (REQ-K-4). Every FFI boundary has panic guards; faults follow `on_plugin_fault`, per engine.

**Acceptance (spec section 17, M4):**
1. Example plugin loaded and driving entities (AT-8, AT-7).
2. All plugin failure tests pass (AT-4, gate 13).
3. A C example compiles against the header (AT-9, and AT-2 for the header itself).

## Compatibility (A-001 freeze; M3 kept)
M0-M2 are frozen (additive only); M3 is not frozen but every M3 test and golden value must keep passing.
### What changes in existing crates, and why it is additive
- `umbra-core` (M0-frozen): new default methods only (`Behavior::batch`, `BehaviorInstance::as_any_mut`),
  new items (`BehaviorBatch`, `BatchItem`, `tick_each`, `PluginFaultPolicy`). No existing signature,
  variant or field changes. Every existing `Behavior`/`BehaviorInstance` impl compiles unchanged.
- `umbra-kernel`: the private `BehaviorSlot` gains a field; the Behavior phase gains a grouped path taken
  only when `Behavior::batch()` is `Some`. No public item changes except one new `#[doc(hidden)]`
  diagnostic method, `Kernel::behavior_scratch_capacity` (the AT-6 growth probe, ASM-125 a); behaviors without a batch run the M3
  code path byte for byte (ADR 0020 amendment).
- `umbra-templates`: `Scenario` (never built literally by M2/M3 tests) gains `plugin_paths` and
  `on_plugin_fault`; new reader keys `plugin_paths`, `on_plugin_fault`; `scenario.v1.schema.json` gains two
  optional properties; one new pub function. `plugins` stays an unknown key, so the M2 tests
  `unknown_key_in_the_scenario_table_is_unknown_key` and the fixture `unknown_scenario_key.toml` pass as
  they are (ADR 0022). `SCHEMA_VERSION` stays 1.
- `umbra-engine`, `umbra-cli`: new functions, re-exports, `#[non_exhaustive]` enum variants
  (`EngineError::PluginFault`, `EngineError::PluginHostInUse`, `ScenarioError::Plugin`), a new flag and a
  new command (`list-plugins`). Structs that tests build literally (`EngineConfig`, `RunOptions`,
  `SpawnSpec`, `RouteSpec`, `EntityInit`, `RouteInit`, `KernelConfig`) get **no** new fields; plugins are
  attached with `Engine::attach_plugins`. `standard_registry()` and `builtin_registry()` keep their
  contents (no plugins).
- No M0-M3 test, fixture or golden file is edited, except the pinned xtask test-root list in
  `xtask/tests/check_unsafe.rs`, which gains one line per new xtask test file (WI-2/WI-4 precedent; step 4
  adds `tests/build_plugins.rs`). No `#[ignore]` is added to an existing test.

### `umbra-plugin-api` (ADR 0019, ADR 0020, ADR 0021; provisional until WI-14)
Rust source is the single truth; cbindgen generates the C header. Every function-pointer field is `Option`
(ADR 0019). Headed structs list `abi_version: u32, struct_size: u32` literally (nit). No struct has
implicit padding; gaps are named `reserved_N` fields that writers zero and readers ignore (R-B1).
```rust
use core::ffi::c_void;
use core::marker::{PhantomData, PhantomPinned};

pub const UMBRA_ABI_VERSION_MAJOR: u32 = 0;
pub const UMBRA_ABI_VERSION_MINOR: u32 = 0;
pub const UMBRA_ABI_VERSION: u32 = (UMBRA_ABI_VERSION_MAJOR << 16) | UMBRA_ABI_VERSION_MINOR;
pub const UMBRA_INTENT_SET_VERSION: u32 = 1;          // equals umbra_core::INTENT_SET_VERSION (host test)
// Caps (R-M2)
pub const UMBRA_MAX_CAPABILITIES: usize = 256;
pub const UMBRA_MAX_ID_LEN: usize = 128;              // equals umbra_core::MAX_ID_LEN (host test)
pub const UMBRA_MAX_SCHEMA_LEN: usize = 1 << 20;      // 1 MiB
pub const UMBRA_MAX_METADATA_LEN: usize = 1 << 16;    // 64 KiB
pub const UMBRA_MAX_ERROR_LEN: usize = 4096;          // longer messages truncated at a char boundary
pub const UMBRA_MAX_INTENTS_PER_ITEM: usize = 64;     // per batch item per call

pub type UmbraToken = u64;           // opaque host token (host_ctx, sink ctx, RNG), generation-checked (R-B4)
pub type UmbraCode = i32;            // UMBRA_OK 0, UMBRA_ERR_PANIC 1, UMBRA_ERR_INVALID_ARGUMENT 2,
                                     // UMBRA_ERR_PARAMS 3, UMBRA_ERR_UNSUPPORTED 4, UMBRA_ERR_INTERNAL 5,
                                     // UMBRA_ERR_STATE 6 (outside lifecycle or call scope)
pub type UmbraCapabilityKind = u32;  // UMBRA_CAPABILITY_BEHAVIOR 1; reserved: MOTION_MODEL 2, NETWORK_ADAPTER 3,
                                     // SENSOR 4, COMPONENT 5, CONDITION 6, ACTION 7 (rejected as unsupported in v0)
pub type UmbraStatus = u32;          // UMBRA_STATUS_UNSET 0, SUCCESS 1, FAILURE 2, RUNNING 3 (R-B2)
pub type UmbraIntentKind = u32;      // MOVE_TO 1, FOLLOW_ROUTE 2, SET_SPEED 3, SET_HEADING 4, HOLD 5,
                                     // FIRE 6, SPAWN 7, DESPAWN 8, CUSTOM 9 (0 invalid)
pub type UmbraValueType = u32;       // BOOL 1, NUMBER 2, INTEGER 3, STRING 4, ENTITY 5, POSITION 6 (0 invalid)
pub type UmbraLogLevel = u32;        // ERROR 1, WARN 2, INFO 3, DEBUG 4, TRACE 5 (0 invalid)

// Frozen value primitives (no header, ADR 0019)
#[repr(C)] #[derive(Clone, Copy)] pub struct UmbraStr { pub ptr: *const u8, pub len: usize }   // UTF-8, not NUL-terminated
#[repr(C)] #[derive(Clone, Copy)] pub struct UmbraVec3 { pub x: f64, pub y: f64, pub z: f64 }
#[repr(C)] #[derive(Clone, Copy)] pub struct UmbraQuat { pub w: f64, pub x: f64, pub y: f64, pub z: f64 }
// Opaque plugin-owned handles: excluded from cbindgen export, declared in `after_includes` as
// `typedef struct UmbraBehavior UmbraBehavior;` (R-M6). The host never dereferences them.
#[repr(C)] pub struct UmbraBehavior { _p: [u8; 0], _m: PhantomData<(*mut u8, PhantomPinned)> }
#[repr(C)] pub struct UmbraInstance { _p: [u8; 0], _m: PhantomData<(*mut u8, PhantomPinned)> }

#[repr(C)] pub struct UmbraErrorSink { pub abi_version: u32, pub struct_size: u32, pub ctx: UmbraToken,
    pub set: Option<unsafe extern "C" fn(ctx: UmbraToken, message: UmbraStr)> }       // first message wins
#[repr(C)] pub struct UmbraHostApi { pub abi_version: u32, pub struct_size: u32,
    pub host_ctx: UmbraToken,                                                          // one per image
    pub log: Option<unsafe extern "C" fn(host_ctx: UmbraToken, level: UmbraLogLevel, message: UmbraStr) -> UmbraCode>,
    pub rng_next_u64: Option<unsafe extern "C" fn(host_ctx: UmbraToken, rng: UmbraToken, out: *mut u64) -> UmbraCode>,
    pub rng_next_f64: Option<unsafe extern "C" fn(host_ctx: UmbraToken, rng: UmbraToken, out: *mut f64) -> UmbraCode> }  // [0, 1)
#[repr(C)] pub struct UmbraPluginDescriptor { pub abi_version: u32 /* = required ABI, REQ-P-3 */, pub struct_size: u32,
    pub id: UmbraStr, pub name: UmbraStr, pub version: UmbraStr,                       // PluginId, text, semver
    pub capabilities: *const UmbraCapability, pub capability_count: usize,
    pub init: Option<unsafe extern "C" fn(host: *const UmbraHostApi, err: *const UmbraErrorSink) -> UmbraCode>,
    pub shutdown: Option<unsafe extern "C" fn()> }
#[repr(C)] pub struct UmbraCapability { pub abi_version: u32, pub struct_size: u32,
    pub kind: UmbraCapabilityKind, pub reserved_0: u32, pub id: UmbraStr,
    pub version: UmbraStr /* empty = plugin version */, pub param_schema: UmbraStr /* JSON, ADR 0009 subset */,
    pub metadata: UmbraStr /* kind-specific JSON, may be empty */, pub vtable: *const c_void }
#[repr(C)] pub struct UmbraBehaviorVTable { pub abi_version: u32, pub struct_size: u32,
    pub configure: Option<unsafe extern "C" fn(params: UmbraStr, out: *mut *mut UmbraBehavior, err: *const UmbraErrorSink) -> UmbraCode>,
    pub destroy_behavior: Option<unsafe extern "C" fn(behavior: *mut UmbraBehavior)>,
    pub instantiate: Option<unsafe extern "C" fn(behavior: *mut UmbraBehavior, rate_hz: u32, out: *mut *mut UmbraInstance, err: *const UmbraErrorSink) -> UmbraCode>,
    pub destroy_instance: Option<unsafe extern "C" fn(instance: *mut UmbraInstance)>,
    pub tick_batch: Option<unsafe extern "C" fn(batch: *const UmbraBehaviorBatch, err: *const UmbraErrorSink) -> UmbraCode>,
    pub halt: Option<unsafe extern "C" fn(instance: *mut UmbraInstance) -> UmbraCode>,            // required, idempotent
    pub halt_running: Option<unsafe extern "C" fn(instance: *mut UmbraInstance) -> UmbraCode>,    // optional: null = halt
    pub set_input: Option<unsafe extern "C" fn(instance: *mut UmbraInstance, param: UmbraStr, value: *const UmbraValue /* null = unset */, err: *const UmbraErrorSink) -> UmbraCode>,
    pub output: Option<unsafe extern "C" fn(instance: *mut UmbraInstance, port: UmbraStr, sink: *const UmbraValueSink) -> UmbraCode> }
#[repr(C)] pub struct UmbraBehaviorBatch { pub abi_version: u32, pub struct_size: u32,
    pub tick: u64, pub rate_hz: u32, pub reserved_0: u32,
    pub items: *const UmbraBehaviorItem, pub count: usize,
    pub statuses: *mut UmbraStatus,          // `count` plain u32s, host pre-fills UNSET; the only out-values (R-B2)
    pub intents: *const UmbraIntentSink }
#[repr(C)] pub struct UmbraBehaviorItem { pub abi_version: u32, pub struct_size: u32,     // read-only for the plugin
    pub behavior: *mut UmbraBehavior, pub instance: *mut UmbraInstance,
    pub entity: *const UmbraEntityView, pub rng: UmbraToken }
#[repr(C)] pub struct UmbraEntityView { pub abi_version: u32, pub struct_size: u32,
    pub id: u64, pub position: UmbraVec3, pub velocity: UmbraVec3, pub orientation: UmbraQuat,
    pub force: UmbraStr /* empty = none */,
    pub has_route: u8, pub route_complete: u8, pub reserved_0: [u8; 6],
    pub route_next: usize, pub route: *const UmbraVec3, pub route_len: usize,
    pub contacts: *const UmbraContact, pub contact_count: usize }                       // contacts sorted by id
#[repr(C)] pub struct UmbraContact { pub abi_version: u32, pub struct_size: u32,
    pub entity: u64, pub position: UmbraVec3, pub velocity: UmbraVec3, pub force: UmbraStr, pub range_m: f64 }
#[repr(C)] pub struct UmbraIntent { pub abi_version: u32, pub struct_size: u32,
```

**Image table (R-B5, ADR 0021; amended after the ABI re-review, RR-M1/RR-M2/RR-M3):** a process-wide
`Mutex<ImageTable>` plus a `Condvar` in `umbra-plugin-host` (the one piece of persistent process-global
state, mirroring the OS loader's own table; ASM-122). Keys: canonical library path (before opening) and
the address of `umbra_plugin_entry` (after opening, before calling it); entries hold `Weak<LoadedImage>`
and a lifecycle state `Loading | Live | Closing`. A load that finds `Loading` or `Closing` waits on the
condvar and retries; a `Live` image is reused (no entry call); a closed one starts a **new lifecycle**
(entry called exactly twice again with a new leaked `UmbraHostApi` and a new `host_ctx`, then `init`). Dead
weak entries are pruned lazily. The table lock is never held while plugin code runs or while an
`Arc<LoadedImage>` may drop. A `LoadedImage` holds the library, the lifecycle's leaked `UmbraHostApi` and
`host_ctx`, the copied descriptor, `init` state, a "tainted" flag for logging, the sticky `keep_loaded`
flag (set if any host asked) and the blocking per-image call lock; it calls `shutdown` (only if `init`
succeeded) and closes the library (unless `keep_loaded`) when its last `Arc` goes, marking the key
`Closing` meanwhile.
**Call records (RR-B1, RR-M2):** a thread-local stack of in-progress plugin calls, each entry = (image id,
call generation, item tokens of a batch call), pushed for every call into a plugin (`init`, `configure`,
`instantiate`, `tick_batch`, `halt*`, `set_input`, `output`, `destroy_*`, `shutdown`) and popped after it.
Every host callback resolves its tokens against the top entry for that image on the calling thread only;
no entry (another thread, after `shutdown`) is `UMBRA_ERR_STATE` without any lookup. A call into an image
that already has an entry on the current thread's stack is re-entry: a fault, and the call lock is not
taken. Tokens: `u32` generation (high) + `u32` index (low), 0 invalid; checked, never dereferenced.
**Lock order (RR-M2):** (1) image table, never held across plugin code or an `Arc<LoadedImage>` drop;
(2) per-image call lock, blocking, held during the plugin call; (3) per-host fault state, a leaf taken
after (2) inside callbacks; (4) `PluginLog`, a leaf that never calls into the host. Load flags (R-M4): Linux `os::unix::Library::open(path, RTLD_NOW | RTLD_LOCAL)`;
Windows `os::windows::Library::load_with_flags(path, LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR |
LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`; absolute paths only (`std::path::absolute`, or canonical with `\\?\`
stripped), never `SetDefaultDllDirectories`; the entry symbol is read as a raw pointer and null-checked.
**Descriptor copy (R-M2):** bounds, alignment, `checked_mul`, caps and per-struct major/size rules of
ADR 0019 before every `from_raw_parts`; everything copied to owned values; the entry is called exactly
twice per image lifecycle, at the first load, with the same `UmbraHostApi*`, and must return the same
pointer (`UnstableEntry` otherwise); hosts that reuse a live image never call it (re-review RR-m4).
**Bridge (private):** `PluginFactory` (`Factory<dyn Behavior>`: `build` = `configure`; panics, errors and an
OK with a null handle become `BuildError`), `PluginBehavior` (`Behavior`: `instantiate`; `batch()` returns
the capability's shared `Arc<CapabilityBatch>`), `PluginInstance` (`BehaviorInstance`: holds an `Arc` to its
`PluginBehavior`, so instances die first; `tick` = batch of one, `halt`, `halt_running` (vtable entry or
`halt`), `set_input`/`output` through `UmbraValue`, `as_any_mut`), `CapabilityBatch` (`BehaviorBatch`:
marshals all items into reused scratch `UmbraEntityView`/`UmbraContact`/`UmbraVec3`/`UmbraBehaviorItem`
buffers written in the plugin's minor, pre-fills `statuses` with `UNSET`, opens a call record (generation,
item tokens), one `tick_batch` call, buffers intents per item, closes the record, then commits intents and
statuses only if the call was clean; otherwise every item is Failure with no intents). Raw pointers to
kernel data are derived with `&raw` and the `&mut` is untouched during the call; routes are copied (core
`Ecef` is never cast). *(amended after the ABI re-review: RR-B1, replaces `try_lock`)* Every call into one
plugin takes its image's call lock **blocking**, so contention from other threads (parallel tests, two
engines) only waits and never faults (REQ-K-4); only same-thread re-entry, found through the call-record
stack, is a fault; a poisoned lock faults the capability (ADR 0019); this serialisation is what makes the
`unsafe impl Send/Sync` of the handle types sound. Fault state: a per-host set of faulted capabilities and
the pending abort (R-M3); `destroy_*` is still called on faulted capabilities. *(RR-m2)* Each
`PluginFactory` is bound to its host: in `Run` mode `build` succeeds only inside the build scope opened by
the engine the host is attached to (`instantiate_with_plugins`), otherwise it returns a `BuildError`
("plugin host not attached to this engine"), so a cloned registry cannot build plugin behaviors for an
engine that does not own the host's fault state.
Interface mapping: `metadata` and schema -> `ComponentInfo::new(schema description, Provenance::Plugin,
version).with_param_type(..).with_output(..).with_result(..)`, checked for consistency (ADR 0020).

## Risks (milestone level)
| Risk | Mitigation |
|---|---|
| A layout or convention mistake frozen by REQ-P-2 | ABI 0.0 provisional until WI-14, freeze review at WI-16 (R-M10); no implicit padding and pinned layouts (AT-1); generated C asserts (WI-4, directly after WI-3) |
| Undefined behavior at the boundary (null function pointers, invalid enums or `bool`, dangling views, stale host contexts) | ADR 0019 rules (`Option` function pointers, integer enums, `u8` booleans, call-scoped data pointers, `u64` tokens checked against call records, bounds and caps, copy at load); tests for each row |
| A panic or exception unwinds across FFI | `catch_unwind` in every SDK export and host callback, payload dropped inside a nested guard; Rust's abort-on-unwind at `extern "C"` as the backstop; C++ authors told to use `noexcept`; panic test per callback |
| Several hosts or loads share one library image | Process-wide image table keyed by path and entry address before the entry call (R-B5); per-host fault state; AT-4 two-hosts row |
| Determinism broken by plugins, batching or fault history | Host RNG through per-item tokens, time in calls, deterministic load and call order, group order by first id, whole-batch discard, fault state per engine; AT-6, AT-7 (incl. second engine), 4-process test |
| M3 behavior or golden hashes move | Batched path only when `batch()` is `Some`, unbatched branch kept byte for byte; compatibility proof items 1-4; gate 4 unchanged targets |
| `dlclose` of a Rust cdylib with thread-locals crashes at exit (macOS, sometimes Linux) | Unload-ordering tests; `HostOptions::keep_loaded` already available as the fallback |
| Windows loading and MSVC compilation | Explicit load flags and absolute paths (R-M4), `cc`; the human runs the full gate on Windows before `m4-done` |
| Missing prerequisites (`cbindgen`, C compiler) or offline `cargo fetch` for `libloading`/`cc` | WI-1 checks and pins; `docs/build.md` prerequisites; xtask exit 2 with the install line |
| Test time and flakiness from building plugin libraries inside tests | One helper, unique package directories per variant (R-M8), `OnceLock`, `--offline --locked`; time recorded in WI-10 |
| A future rustc changes the `no_mangle`/`forbid` interaction | WI-2 regression fixture fails first |
| Soundness of `unsafe impl Send/Sync` for bridge handles | Blocking per-image call lock (re-review RR-B1: contention waits, never faults; same-thread re-entry found through the thread-local call stack is a fault), poisoning handled, documented lock order (RR-M2); `// SAFETY:` and a two-thread contention test |
| Timing-dependent faults or deadlocks in the host | No `try_lock`; tokens resolved on the calling thread only; image table never held across plugin code or an `Arc<LoadedImage>` drop; lifecycle states with a condvar (RR-M1) |
| Scope creep into other kinds or a richer host API | Out-of-scope list; kind numbers reserved only; ADR 0021 staging |
