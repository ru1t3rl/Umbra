## Goal
Every plugin kind of REQ-P-4 except the undefined `component` kind loads through the one loader and
registry, with a third-party-style example per kind; ships and aircraft move with built-in models; runs
can be recorded and replayed, reproducing their state hashes, including runs fed by real UDP traffic and
API commands; `Spawn` and `Despawn` intents take effect.

The parts:
- ABI 0.2: `motion_model`, `sensor`, `condition`, `action` kinds with per-call terrain and blackboard
  services (ADR 0050). The network kind exists since M6 (ABI 0.1, M6 H7 a); M7 adds its example.
- `builtin.air.kinematic` and `builtin.sea.kinematic` (ADR 0051).
- `Spawn`/`Despawn` applied at the engine tick boundary (ADR 0052).
- Recording format v1 in a new crate `umbra-record` (ADR 0053), replay with verification (ADR 0054),
  optional state hash v3 (ADR 0055).
- Example plugins (motion, sensor, condition, action, network = the REQ-N-8 recording adapter) and
  `umbra new-plugin` (ADR 0056).
- API 1.2.0: recording status (ADR 0057), landed early for the M8 track.

A scenario that uses none of this runs exactly as before: same goldens, same stdout.

**Acceptance (spec section 17, M7):**
1. A third-party-style example plugin of each kind in `examples/` (AT-1..AT-6).
2. Replay reproduces state hashes (AT-7..AT-11).

**Gate check (step 1):** M6 is ticked in `docs/milestones.md` with evidence: tag `m6-done`, full local gate
on Linux (3019 passed, 1 ignored; gate 4 35; gate 13 45). M3b (optional) is not a prerequisite. Windows and
macOS are not run (human decision 2026-10-19); NFR-3 stays unverified.

## Compatibility (A-001 freeze; M3-M6 kept; ABI 0.0/0.1 extended only by appending)
M0-M2 are frozen: additive changes only, edits above the first `#[cfg(test)]`, no edits to existing
`tests/`, `fixtures/` or `examples/` files except the human-approved list below. Every M3-M6 test,
fixture and golden keeps passing unchanged.

**Goldens that must stay byte-identical** (`scripts/gates.sh`, with and without a 45 Hz `umbra.toml`):
`849026656b7b42d2` (walking_skeleton), `3a7bfda0a76111b9` (patrol_and_engage, tick 4200),
`88954c5dc6b52b48` (plugin_wander), `3cc077a4c83c4a63` (plugin_c_circle). They hold by construction:
- the state hash default stays v2 (ADR 0055: v3 is opt-in);
- no golden scenario emits `Spawn` or `Despawn` (checked: no match in `examples/` or the built-in leaves),
  so the new lifecycle step does nothing;
- `builtin.ground.kinematic` is untouched (air/sea get their own helper, ASM-611);
- the c-circle plugin's behavior structs are unchanged by ABI 0.2.
`run` stdout and stderr must stay byte-identical to the `m6-done` binary for all four (WI-4, WI-13, WI-24).

**Plugin ABI (human decision H1).** ABI 0.0 and 0.1 layouts stay byte-identical (every size and offset pin).
ABI 0.2 adds constants, new structs and four supported kinds. Edits that are not pure additions:
1. `UMBRA_ABI_VERSION_MINOR` 1 -> 2 (header regenerated, gate 11; size tables gain a minor-2 row equal to
   minor 1 for every existing struct).
2. Frozen test literals, each rewritten **relative to `UMBRA_ABI_VERSION_MINOR`** (or to the support
   table's counts) so that a later minor needs no edit (ASM-641):
   - `crates/umbra-plugin-host/tests/manifest.rs` `given_a_manifest_with_a_newer_abi_minor_then_rejected_without_opening` (`"0.2"`);
   - `crates/umbra-plugin-host/tests/descriptor.rs` `descriptor_abi_minor_is_newer` (`2`);
   - `crates/umbra-plugin-host/src/descriptor.rs` unit test `header_checks_major_minor_and_size` (`(2, own32)`);
   - `crates/umbra-plugin-api/tests/layout.rs::abi_version_packs_major_and_minor` (`(0, 1, 1)`) and the
     count literals (`HEADED`, constants, reserved fields) in `layout.rs` and the offsets count in

3. `examples/plugins/c-circle/plugin.toml` `abi = "0.1"` -> `"0.2"` and its README line (compiled against

`umbra-test-plugin`, `dis`, `cli_list_plugins.rs`, `build_plugins.rs` are unchanged. WI-7 starts with a

**Registry.** `ComponentKind` already has `MotionModel`, `Sensor`, `Condition`, `Action`; no registry kind

### ABI 0.2 (ADR 0050)
Struct and vtable list in ADR 0050; exact field order by the plugin-abi-engineer. Constants:
`UMBRA_ABI_VERSION_MINOR = 2`; kinds 2, 4, 6, 7 supported for descriptors of minor >= 2 (minor-0/1
descriptors naming them are rejected at `capabilities[i].kind` as today); `UMBRA_OWNERSHIP_OWNED` 1,
`UMBRA_OWNERSHIP_REMOTE` 2; `UMBRA_CONDITION_UNSET` 0xFF; caps `UMBRA_MAX_CONTACTS_PER_SENSE` (4096) and
`UMBRA_MAX_INTENTS_PER_ITEM` reused for actions. Host bridges:
```rust
// umbra-plugin-host::bridge
pub(crate) struct PluginMotionFactory;   // Factory<dyn MotionModel>: configure -> PluginMotionModel
pub(crate) struct PluginMotionModel;     // impl umbra_core::MotionModel; step marshals state+intents, terrain token for the call
pub(crate) struct PluginSensorFactory;   pub(crate) struct PluginSensor;      // impl umbra_core::Sensor
pub(crate) struct PluginConditionFactory; pub(crate) struct PluginCondition; // impl umbra_core::Condition
pub(crate) struct PluginActionFactory;   pub(crate) struct PluginAction; pub(crate) struct PluginActionInstance;
```
`PluginCapability<V>` (M6, generic over the vtable) is reused, so calls, faults and verdicts are shared.
Service tokens live in the call record next to the RNG token (ADR 0021 RR-M2).

Ordering inside a tick with a recorder: commands (recorded as applied, `before_tick`), ingest (the tap
records each adapter's poll result, then the manager processes it), `Kernel::tick`, `Spawner::apply`,
network publish, then the `hash` record if due. Replay feeds the same points.

### Determinism and ordering guarantees (REQ-K-4)
- Spawns in (spawner id, emission order), then despawns in id order; new ids monotonic; streams keyed by id.
- Plugin calls of the new kinds happen in the kernel's existing order (motion and perception in id order;
  leaves in graph order). Services answer only from call arguments and the call's terrain.
- Recordings contain no wall-clock values and are byte-identical across runs of the same inputs; records
  appear in tick order, within a boundary in application order (`seq`).
- Replay applies inputs at exactly the recorded points; replay of a replay is identical.
