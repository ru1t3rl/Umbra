# M2 Templates and scenarios: implementation plan

Status: **Draft for human review** (architect, 2026-10-17). Skill: `implement-milestone`, step 3.
Base: `develop` at 44c7ad8 (tag `m1-done`).

## Goal
Entities come from user-editable TOML: template files (with single inheritance) and scenario files
(seed, clock, tick rate, terrain, placements by ECEF or lat/lon/alt, initial routes). One validation
pipeline reports every error with file, line and column. Component IDs resolve through one registry
(D-8) whose components supply their own JSON Schemas. `cgf-cli validate <path>` checks files without
running; `cgf-cli run <scenario.toml>` runs them headless (REQ-S-1). The M1 hard-coded demo becomes an
example scenario file (human decision 2026-10-17) and `cgf-cli demo` is removed.

**Acceptance (spec section 17, M2):**
1. REQ-T-1..6 tested, including inheritance-cycle and unknown-ID errors (AT-1..AT-6).
2. An example scenario with three templates runs (AT-8; it is also the gate-4 determinism subject).

**Gate check (step 1):** M1 is ticked in `docs/milestones.md` with evidence (tag `m1-done`, full local gate
on Linux at 7d34c0e). No CI (ADR 0004); the local gate in `docs/build.md` is the definition of done.

**Human decisions already taken (2026-10-17, not approval items):**
- Tick rates stay whole hertz (ASM-016 unchanged). Scenario `tick_rate_hz` is a positive integer; a
  fractional form would come later with a `schema_version` bump.
- `cgf-cli demo` is removed. `cgf_engine::demo` and its hard-coded layout go away; the M1 determinism,
  waypoint, placement and CLI tests move onto the scenario path with their guarantees intact (WI-11).

### `cgf-core` additions (ADR 0008)
```rust
// id.rs: one more string ID from the existing macro (ADR 0002 grammar)
string_id!(/// Identifier of a registered component of any kind, e.g. `builtin.ground.kinematic`.
           ComponentId);

// params.rs
pub use serde_json::Value as ParamValue;
/// A JSON Schema document (object at the root). Validated against the ADR 0009 subset by
/// `cgf-templates`, not here.
#[derive(Debug, Clone, PartialEq)]
pub struct ParamSchema(Arc<serde_json::Value>);
impl ParamSchema {
    pub fn from_json_str(s: &str) -> Result<Self, ParamSchemaError>;   // invalid JSON or non-object root
    pub fn as_json(&self) -> &serde_json::Value;
}
#[derive(Debug, Clone, PartialEq, thiserror::Error)] #[non_exhaustive]
pub enum ParamSchemaError { #[error("schema is not valid JSON: {0}")] Json(String),
                            #[error("schema root must be a JSON object")] NotAnObject }

// registry.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)] #[non_exhaustive]
pub enum ComponentKind { MotionModel, Terrain, Behavior, Sensor }
impl ComponentKind { pub fn noun(self) -> &'static str; }   // "motion model", "terrain provider", ...

/// Builds one kind of component from validated parameters. Built-ins and (M4) plugin bridges
/// implement it identically (REQ-T-1). Called at load time only, never per tick.
pub trait Factory<T: ?Sized>: Send + Sync {
    fn id(&self) -> &ComponentId;
    fn param_schema(&self) -> &ParamSchema;
    /// `params` has passed `param_schema`; may still reject semantic combinations.
    fn build(&self, params: &ParamValue) -> Result<Arc<T>, BuildError>;
}
#[derive(Debug, Clone, PartialEq, thiserror::Error)] #[error("{message}")]
pub struct BuildError { pub message: String, pub param: Option<String> /* top-level key, for the location */ }

/// The single component registry (D-8). Lookups are by kind and ID; iteration is in ID order.
#[derive(Default)]
pub struct Registry { /* BTreeMap<ComponentId, Arc<dyn Factory<dyn MotionModel>>>, same for dyn TerrainProvider */ }
impl Registry {
    pub fn new() -> Self;
    pub fn register_motion_model(&mut self, f: Arc<dyn Factory<dyn MotionModel>>) -> Result<(), RegistryError>;
    pub fn register_terrain(&mut self, f: Arc<dyn Factory<dyn TerrainProvider>>) -> Result<(), RegistryError>;
    pub fn motion_model(&self, id: &ComponentId) -> Option<&Arc<dyn Factory<dyn MotionModel>>>;
    pub fn terrain(&self, id: &ComponentId) -> Option<&Arc<dyn Factory<dyn TerrainProvider>>>;
    /// Kind-generic view for validation and `schema` output. `Behavior`/`Sensor` are always empty in M2.
    pub fn param_schema(&self, kind: ComponentKind, id: &ComponentId) -> Option<&ParamSchema>;
    pub fn ids(&self, kind: ComponentKind) -> Vec<&ComponentId>;          // sorted
}
#[derive(Debug, Clone, PartialEq, thiserror::Error)] #[non_exhaustive]
pub enum RegistryError { #[error("{kind} {id} is already registered")] Duplicate { kind: &'static str, id: ComponentId } }

// terrain.rs: lets the engine pass an Arc from a factory to Kernel::new(Box<dyn TerrainProvider>)
impl<T: TerrainProvider + ?Sized> TerrainProvider for Arc<T> { /* delegate */ }
```
`Behavior`/`Sensor` kinds exist so the loader can say "unknown behavior `x` (no behaviors are registered
in this build)" through the same lookup; their maps and `register_*` methods arrive in M3 with the
`Behavior`/`Sensor` traits (ASM-055). No ABI kind is added (REQ-P-4 unchanged).

### Pipeline (one pipeline for templates, scenarios and overrides, DRY)
1. **Read** each file (sorted path order). I/O failure is an `io` diagnostic on that path.
2. **Parse** with `toml::de::DeTable::parse_recoverable` into the located tree (`value.rs`); every syntax
   error becomes a `syntax` diagnostic; datetimes and `nan`/`inf` become `unsupported_value`. A file with
   syntax errors stops here (its tree is unreliable); other files continue.
3. **Version**: `schema_version` must be an integer; `> 1` is `unsupported_schema_version` and the file
   stops here; `< 1` is `invalid_value`; missing is `missing_key`.
4. **Structure** (`reader.rs`): every known key type-checked, every unknown key reported, IDs checked
   with the ADR 0002 grammar (`invalid_id`), numbers checked for range (finite, signs). All errors
   in the file are collected.
5. **Set** (templates): `duplicate_id` (note at the first definition), `unknown_template` for `extends`,
   `inheritance_cycle` (one diagnostic per cycle, at the `extends` of the smallest ID in it, notes along
   the chain `a -> b -> a`). Templates that depend on a broken template are not resolved and produce no
   cascade diagnostics (the root cause is reported once).
6. **Resolve** each template in ID order: merge the chain root-first (ADR 0010 rules), keeping each
   value's origin (file and span). Look up IDs in the registry (`unknown_id`, notes list registered IDs
   of that kind, or "none are registered in this build"). Validate params against the compiled schema
   (`missing_param`, `param_wrong_type`, `param_out_of_range`, `unknown_param`), then dry-run
   `Factory::build` (`param_invalid` from `BuildError`). Inherited errors located in a parent file
   are deduplicated.
7. **Scenario**: structure as in 4; every `[[entities]]` entry resolved against the template set;
   `overrides` merged over the resolved template and re-validated (errors located in the scenario);
   positions and waypoints converted with `Geodetic::from_degrees` / `Ecef` (`invalid_value` at the
   position table); `duration_ticks = ceil(duration_s * hz)` must be >= 1 and fit `u64`. Duplicate
   non-empty `name`s are `duplicate_name`. Any error anywhere in the template set fails the scenario
   (ASM-058).
8. **Sort and deduplicate** diagnostics; `Ok` only if there are none.

Determinism: maps are `BTreeMap`; discovery sorts paths; entities keep file order; no randomness, no
time; the result is a pure function of file contents, paths and the registry. Parameters are passed to
factories as `ParamValue` built from the located tree, not re-parsed from text.

## Risks (milestone level)
| Risk | Mitigation |
|---|---|
| `toml` 1.1 lacks a recoverable, spanned parse API as assumed | WI-1 spike; fallback `toml_edit` spans with first-syntax-error-only (ASM-054); semantic errors (the REQ-T-2 list) are all-errors either way |
| Error cascades (one root cause, dozens of messages) or silently suppressed real errors | Explicit suppression rule (dependents of broken templates only), dedup by (code, location, message); AT-2 tests both directions |
| Determinism: load order depends on `read_dir` order or map iteration | Sorted discovery, BTreeMap, file-order entities; AT-9 shuffle tests; gate 4 on the scenario |
| Determinism: `serde_json` `preserve_order` enabled by feature unification later (e.g. `utoipa` in M5) | Param maps are only looked up by key, never iterated for simulation; `ParamValue` never hashed; reviewer checks `Cargo.lock` features in M5 |
| Float parsing differences TOML vs JSON | Values flow TOML text -> `f64` (std, correctly rounded) -> `ParamValue` without re-parsing text; integer and float spellings tested equal |
| JSON Schema subset too small for plugin authors (M4), affecting ABI expectations (REQ-P-3) | ADR 0009 revisit trigger; additive keywords; `CompiledSchema` API isolates callers |
| Format v1 becomes a contract too early (route key, no abstract templates) | ADR 0010 additive-evolution policy; route defined as "initial route" that survives M3 |
| Owned/remote (REQ-K-5): scenarios could later be used to inject remote entities | M2 placements are always `Owned`; no ownership key in the format (ASM-059) |
| Losing M1 guarantees when the demo is removed | WI-11 maps each M1 AT to a successor test by name; reviewer checks the mapping |
| Windows paths and CRLF in diagnostics (NFR-3, still unverified) | CRLF line-index tests; tests compare paths by components |
| Untrusted file content panics the loader (NFR-2) | No `unwrap`/`expect`/indexing on parsed data; `parse_never_panics` proptest; checked arithmetic for `duration_ticks` |
