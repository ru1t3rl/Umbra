# M3 Declarative behavior: implementation plan

Status: **Approved** (architect draft 2026-10-17; human decisions 2026-10-17, see "Decisions" and the running log). Skill: `implement-milestone`, step 3.
Base: `develop` at 8580dfa (M2 tagged `m2-done`; spec v0.2 with amendment A-001, decisions D-26/D-27).

## Goal
Entities get behavior from data. A behavior graph (`*.behavior.toml`) is a behavior tree with `fsm` and
`subgraph` nodes, loaded and validated by the M2 pipeline (same diagnostics, `schema_version` handling,
registry, JSON Schema subset). Graphs, conditions and actions resolve by ID through the one registry
(D-8); a graph's ID is a valid template `[behavior] ref`. A kernel Perception phase fills per-entity
contacts from the `builtin.visual` sensor; the Behavior phase ticks each Owned entity's behavior instance,
which emits intents only; motion turns them into movement. A catalog data model lists node types,
conditions, actions and graphs with schema, version and provenance (REST exposure is M5).

**Acceptance (spec section 17, M3):**
1. A patrol-and-engage scenario (a tree with an embedded FSM and a reusable subgraph) runs
   deterministically (AT-16, gate 4 via AT-12).
2. Swapping a behavior needs only a template change (AT-17).
3. REQ-B-6..17 tested, including cycle, version-mismatch and scoped-blackboard isolation (AT-1..AT-13).
4. All M2 template/scenario fixtures still pass unchanged (AT-18, compatibility checklist below).

**Gate check (step 1):** M2 is ticked in `docs/milestones.md` with evidence (tag `m2-done`, full local
gate on Linux at 673a963, 927 tests). No CI (ADR 0004); the local gate in `docs/build.md` is the
definition of done.

**Approvals:** ADRs 0011-0017 Accepted by the human on 2026-10-17 (spec D-28..D-34), including the one
approved M2 test edit (ADR 0011) and dynamic input bindings for subgraphs (ADR 0014).

### What changes in M2-era code, and why it is additive
- New enum variants only in `#[non_exhaustive]` enums (`Intent`, `DiagnosticCode`, `ComponentKind`,
  `EngineError`); no variant or field of an existing type changes.
- New fields only on structs that no M1/M2 test constructs: `ResolvedTemplate`, `Placement`, `Scenario`
  (`cgf-templates`), `EntitySnapshot` (`#[non_exhaustive]`). Structs that tests build literally
  (`EntityInit`, `RouteInit`, `KernelConfig`, `SpawnSpec`, `RouteSpec`, `EngineConfig`, `RunOptions`) get
  **no** new fields; new behavior enters through new functions (`Kernel::spawn_with`,
  `Engine::spawn_with`) and the new type `AgentInit`.
- New trait methods only with default bodies (`TerrainProvider::line_of_sight`).
- Formats: template and scenario files unchanged except the optional placement key `force` (ADR 0015,
  additive per ADR 0010, no `schema_version` bump); `template.v1.schema.json` unchanged;
  `scenario.v1.schema.json` gains one optional property.
- **The one approved M2 test edit** (human, 2026-10-17; justification ADR 0011 / D-28: the new registry
  kinds `Condition` and `Action` make the test's exhaustive match fail to compile, which is the test's
  stated purpose): `cgf-core/src/registry.rs::all_lists_every_kind_once` gains the `Condition` and
  `Action` arms and `COUNT = 6`, nothing else, in its own commit in WI-5, reviewed as a diff of that test
  alone. No other M1/M2 test or fixture changes.

/// A behavior program; parameters are bound when it is built. Shared by entities.
pub trait Behavior: Send + Sync {
    fn id(&self) -> &BehaviorId;
    /// Per-entity (or per-subgraph-node) state, durations converted to ticks at `rate`.
    fn instantiate(&self, rate: TickRate) -> Box<dyn BehaviorInstance>;
}
pub trait BehaviorInstance: Send {
    fn tick(&mut self, ctx: &mut BehaviorContext<'_>, entity: &EntityView<'_>, out: &mut IntentBuffer<'_>) -> Status;
    /// Abandon a Running activation; the next tick starts fresh (blackboard kept, ADR 0014).
    fn halt(&mut self);
    /// Value of a declared output port after the last tick (REQ-B-10); `None` = unset.
    fn output(&self, port: &str) -> Option<&BbValue>;
}
pub trait Condition: Send + Sync {
    fn id(&self) -> &ComponentId;
    /// Success iff true. May write declared blackboard keys (e.g. `store_as`). Never emits intents.
    fn check(&self, ctx: &mut BehaviorContext<'_>, entity: &EntityView<'_>, bb: &mut Blackboard) -> bool;
}
pub trait Action: Send + Sync {
    fn id(&self) -> &ComponentId;
    fn instantiate(&self, rate: TickRate) -> Box<dyn ActionInstance>;
}
pub trait ActionInstance: Send {
    fn tick(&mut self, ctx: &mut BehaviorContext<'_>, entity: &EntityView<'_>, bb: &mut Blackboard, out: &mut IntentBuffer<'_>) -> Status;
    fn halt(&mut self);
}

    pub fn declare(&mut self, key: &str, ty: BbType);
    /// A read-only key for an interface param (ADR 0014); only the runtime writes it, via `input`.

### Graph pipeline (the M2 pipeline, extended)
1. **Read, parse, version, structure**: M2 steps 1-4 unchanged, per graph file (`graph_read.rs` uses
   `Reader`); node names, state/exit/blackboard key names `[a-z][a-z0-9_]*`; `[editor]` checked to be a
   table and dropped.
2. **Set**: `duplicate_id` across graph files and against registered components (note at the first
   definition or "registered as a <kind>"); graphs in files with syntax errors are "broken" and their
   dependents get no cascade errors (ASM-056 rule).
3. **Per graph**: tree shape from `root` (`unknown_node`, `node_reused`, `node_cycle`,
   `unreachable_node`); node settings against `NODE_TYPES` schemas; FSM (`no_initial_state`, unknown
   state/exit names, `duplicate_name`, `unreachable_state` by BFS from `initial`, `invalid_guard`); leaves
   (`unknown_id` with the right kind, params against the leaf schema with `{param}` references checked for
   existence and type, blackboard-key params against `[blackboard]` via `ComponentInfo::blackboard_params`);
   interface (fragments compiled into one object schema; `outputs.from` declared and type-equal).
4. **Subgraph refs**: target is a graph of this load or a registered `Behavior` (`unknown_id`);
   `invalid_version` / `version_mismatch` (note: the target's version and where it is defined);
   `subgraph_cycle` (one per cycle, at the `ref` of the smallest graph ID in it, one note per edge, as
   `inheritance_cycle`); `subgraph_too_deep` (ASM-073); output bindings (`invalid_binding`: unknown port,
   undeclared or wrongly typed parent key, a key bound twice); input bindings `{ key = .. }`
   (`invalid_binding`: undeclared parent key, type not equal to the param's type, the param is used as a
   `{ param }` reference inside the target, `{ key }` outside a `subgraph` node; an unknown param name is
   `unknown_param`; a binding-only param without a binding is `missing_param`).
5. **Call sites**: each `subgraph` node's literal params (after substituting the caller's defaults and
   references; bound params are excluded, a required param counts as given when bound) against the
   target interface (`missing_param`, `unknown_param`, `param_wrong_type`,
   `param_out_of_range`), then substituted leaf params of the target down the chain, trial-built.
6. **Templates**: the M2 template steps run on a scoped loader whose schemas include this load's graph
   interfaces; a template `[behavior] ref` to a graph is checked like any behavior, then step 5 runs for
   it (errors at the template's `params` value). A `{ key = .. }` value there is `invalid_binding` (a
   top-level behavior has no parent blackboard, ADR 0014).
7. **Sort and deduplicate** as M2.
