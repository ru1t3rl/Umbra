# M6 Networking and DIS: implementation plan

Status: **Accepted** by the human on 2026-10-20 (the architect proposed it the same day).
- ADRs 0030-0035 are Accepted. Every recommendation H1-H10 was accepted as written: ABI 0.1 additive
  network kind with the ADR 0019 SDK rule change, the four literal-only M4 edits and the two-line M2 test
  addition; in-house DIS codec with v7 and v6 both in M6; `socket2` 0.6.5 in `umbra-net-dis` only;
  loopback/unicast receive-only defaults with explicit opt-in and a warning; the scope moves of H7; the
  additive ADR extensions of H9; Linux-only evidence; the Wireshark check optional, logged, not a gate.
- Numbering block for this milestone (parallel tracks, `docs/assumptions.md`): ASM-224..ASM-299,
  ADR 0030..0039, decision rows D-49..D-55. Used here: ASM-224..ASM-254, ADR 0030..0035, D-49..D-54.

**Human decision folded in (2026-10-20, recorded in ADR 0030 and ADR 0034):**
1. Networking is a generic, protocol-agnostic abstraction layer. `umbra-net` holds the manager, publish
   policy and thresholds, ghosts, dead reckoning, identity map, echo suppression and the adapter
   trait / plugin interface. Nothing in `umbra-net` or the engine (nor `umbra-core`, `umbra-kernel`) knows
   DIS types, PDUs, site/application/entity ids or DIS enumerations. The neutral model maps to and from
   protocol specifics only inside an adapter. The loopback adapter uses the same interface, and HLA (M9)
   fits it without changes (ADR 0030, "HLA fit"). A dependency-rule test and a source test enforce it
   (WI-1).
2. DIS is one adapter plugin of that layer. DIS v7 (IEEE 1278.1-2012) is the primary target. v6
   (1278.1-1995) is also supported, because its cost is small (ADR 0034: same layouts for the five PDU
   families; only the header and a few status bits differ). The version is chosen by config and isolated
   in a version strategy inside the adapter, with golden packets for each version. The human confirms the
   scope (decision H3).

Base: `develop` at `ac9e01e`, tag `m5-done` (M5 done 2026-10-20, full Linux gate green). Branch `m6`,
worktree `umbra-m6`. M5b runs in parallel on its own branch (A-002); no M6 item waits for it.

## Goal
Two Umbra engines, or Umbra and any other simulation, share entities over the network:
- each engine publishes its owned entities;
- each engine mirrors the other's as Remote ghosts that are dead-reckoned, never ticked and never
  re-published.

The parts:
- `umbra-net` is a protocol-neutral manager. It owns the publish policy (thresholds, heartbeat, minimum
  interval), the identity map, echo suppression, the ghost lifecycle and the entity-type-to-template
  mapping.
- Adapters translate only:
  - an in-memory loopback adapter for tests;
  - the DIS adapter, a plugin built with the public SDK on a new ABI 0.1 network adapter kind.
- The kernel gains ghost dead reckoning in its Ingest phase.
- The engine applies network input and output at the tick boundary.

A scenario without `[[network_adapters]]` runs exactly as before: same goldens, same stdout.

**Acceptance (spec section 17, M6):**
1. Two engine instances exchange entities over DIS on localhost (AT-1, AT-2, AT-3, AT-4).
2. No echo loops (AT-5, AT-6).
3. Golden-packet tests pass (AT-7, AT-8).

**Gate check (step 1):** M5 is ticked in `docs/milestones.md` with evidence: tag `m5-done` and the full
local gate on Linux (2411 tests, 0 ignored). M3b (optional) and M5b (parallel GUI) are not
prerequisites (A-002). Windows and macOS are not run (human decision 2026-10-19); NFR-3 stays
unverified.

### `umbra-net` (ADR 0030-0032)
```rust
pub struct AdapterSettings { pub name: String, pub enabled: bool, pub publish: PublishPolicy, pub ghosts: GhostPolicy }
pub struct PublishPolicy { pub position_threshold_m: f64, pub orientation_threshold: Radians, pub heartbeat: Seconds,
    pub min_interval: Seconds, pub model: DeadReckoning, pub control: bool }
pub struct GhostPolicy { pub timeout: Seconds, pub max: usize, pub max_inbound_per_tick: usize }
pub struct TypeMap { /* NetEntityType -> TemplateId (BTreeMap), default */ }
impl TypeMap { pub fn new(declared: &[(TemplateId, NetEntityType)], overrides: &[(NetEntityType, TemplateId)], default: Option<TemplateId>) -> (Self, Vec<TypeMapWarning>); pub fn resolve(&self, t: Option<&NetEntityType>) -> Option<&TemplateId>; }
pub struct IdentityMap { /* BTreeMap<EntityId, (NetKey, Role)>, BTreeMap<NetKey, EntityId> */ }
impl IdentityMap { pub fn local_key(&mut self, e: EntityId, space: KeySpace) -> Result<NetKey, IdentityError>; pub fn bind_remote(&mut self, k: NetKey, e: EntityId) -> Result<(), IdentityError>; pub fn entity(&self, k: NetKey) -> Option<(EntityId, Role)>; pub fn key(&self, e: EntityId) -> Option<NetKey>; pub fn forget(&mut self, e: EntityId); }

pub struct GhostSpec<'a> { pub source: RemoteSource, pub template: &'a TemplateId, pub force: Option<Force>, pub name: Option<Arc<str>>, pub remote: RemoteState }
pub trait GhostWorld {
    fn create_ghost(&mut self, spec: GhostSpec<'_>) -> Result<EntityId, GhostError>;
    fn update_ghost(&mut self, id: EntityId, remote: RemoteState) -> Result<(), GhostError>;
    fn remove_ghost(&mut self, id: EntityId) -> Result<(), GhostError>;
}
pub struct OwnedMeta { pub template: Option<TemplateId>, pub name: Option<Arc<str>> } // per owned entity, from the engine
pub struct NetworkManager { /* Vec<AdapterSlot> in scenario order */ }
impl NetworkManager {
    pub fn new(slots: Vec<(AdapterSettings, Arc<dyn NetworkAdapterConfig>, TypeMap)>, now: SimTime) -> Result<Self, NetError>; // starts adapters
    pub fn ingest(&mut self, now: SimTime, world: &mut dyn GhostWorld, events: &mut Vec<SimEvent>);
    pub fn publish(&mut self, now: SimTime, owned: &[OwnedView], meta: &BTreeMap<EntityId, OwnedMeta>, entity_types: &dyn Fn(&TemplateId, &str) -> Option<NetEntityType>, events: &[SimEvent]);
    pub fn publish_control(&mut self, now: SimTime, action: ControlAction);
    pub fn set_enabled(&mut self, name: &str, enabled: bool) -> Result<AdapterStatus, ManagerError>;
    pub fn status(&self) -> Vec<AdapterStatus>;   // counters, key space, ghosts, faulted

pub mod loopback { pub struct LoopbackHub; impl LoopbackHub { pub fn new(capacity: usize) -> Arc<Self>; pub fn factory(self: &Arc<Self>, id: ComponentId, key_space: KeySpace) -> Arc<dyn Factory<dyn NetworkAdapterConfig>>; pub fn captured(&self) -> Vec<(String, NetMessage)>; } }
```
The `entity_types` closure resolves a template's `network.<name>.entity_type` once per template; the
engine caches it at load. The final shape of that parameter is the implementer's choice (a precomputed
`BTreeMap<TemplateId, NetEntityType>` per adapter is fine).

Loopback semantics:
- every endpoint created from one hub delivers each published message to every other endpoint's
  bounded queue (capacity per endpoint, drop-and-count);
- delivery happens synchronously inside `publish`, so a later `poll` sees it;
- a `params` key `key_space` lets tests give endpoints distinct ranges, and `echo = true` also delivers
  to self, which the echo-suppression test needs.

### Engine wiring (`umbra-engine::net`; ADR 0030)
- `NetLink { manager: NetworkManager, ghosts: GhostBuilder, meta: BTreeMap<EntityId, OwnedMeta>,
  types: per-adapter BTreeMap<TemplateId, NetEntityType> }`, attached by `Engine::attach_network(link)`.
  It is created in `instantiate`/`instantiate_with_plugins` only when the scenario has
  `[[network_adapters]]`.
- `GhostBuilder` pre-builds one motion model per mappable template at load (identity only, never
  stepped; ASM-241) and implements `GhostWorld` over `Kernel::spawn_remote`, `update_remote` and
  `remove`.
- In `Engine::run` and `Engine::pump`, around each tick: `ingest`, then `Kernel::tick`, then `publish`,
  then `take_abort`. Ghost and inbound events are prepended to `report.events` (ASM-248). When paused
  nothing is called (ASM-240).
- `Session::spawn` and `Session::remove` keep `meta` current. A `SimulationControl` emitted by the
  session also calls `publish_control` (sent only if `[publish] control = true`, ASM-244).
- Validation (`validate_path_with_plugins`) builds every adapter config (a dry-run `configure`) and never
  starts it (ASM-251).
- Shutdown: `NetLink` drop stops every adapter before the plugin host releases its images (field order;
  a test in WI-11 pins it).
- CLI `run`: at `--log-level info` it prints one stderr line per adapter at the end, `info: net <name>:
  published=.. received=.. ghosts=.. echo_dropped=.. unmapped=.. tx_dropped=.. rx_dropped=..
  decode_errors=..` (ASM-250).

Superseded or refined in WI-9 (see `docs/assumptions/M6.md`): no `types` field in `NetLink` (the per-adapter
entity types live in the `AdapterSlot`s, ASM-293); run control comes from `Engine::publish_control`, called by the
handle and the CLI, not from the session (ASM-295); validation needs no code beyond the loader's trial build, which
passes the same factory input as the engine (ASM-296, ASM-401); ghosts are listed through `Session::directory`
(ASM-400).

### `umbra-net-dis` (ADR 0034)
Modules:
- `codec` (pure; `Pdu`, `encode`, `decode`, `DecodeError`);
- `version` (`DisVersion`, `HeaderStrategy` with `V6Header` and `V7Header`, the only place version
  differences live);
- `translate` (SDK message mirror <-> `Pdu`; key packing; type tokens; force, weapon and DRM tables;
  marking; deactivated appearance; timestamps from tick and rate);
- `config` (params schema: `version` 6|7 (default 7), `exercise` (default 1), `site`, `application`
  (required, 1..65534), `mode`, `bind`, `destinations`, `broadcast_address`, `group`, `interface`, `ttl`,
  `forces`, `weapons`, `queue` sizes);
- `transport` (sockets, two threads, bounded queues, join on stop);
- `lib.rs` (`export_plugin!`).

The decoder accepts v6 and v7 alike; `version` selects what is sent (ASM-249). Inbound PDUs of
another exercise id are dropped and counted. Packaged by `cargo xtask build-plugins` as
`target/plugins/dis/` with `plugin.toml` (`abi = "0.1"`).

### Determinism and ordering guarantees (REQ-K-4)
- No `HashMap`; every map is a `BTreeMap` or a `Vec` in scenario order.
- Publish visits Owned entities in `EntityId` order. Local keys are allocated in first-publish order.
- Ingest polls adapters in scenario order and applies messages in delivery order.
- Thresholds, heartbeats and timeouts use `SimTime`. The DIS adapter derives timestamps from the batch
  tick.
- Loopback delivery is synchronous, so two engines over loopback in stepped mode give identical per-tick
  hashes on every run (`net_determinism`, gate 4). Over UDP, the arrival tick of a datagram depends on
  wall timing; such runs are reproducible only from the recorded input stream (M7). Documented in
  `docs/net/README.md`.
