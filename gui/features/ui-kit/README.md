# @umbra/ui-kit

Foundation feature (tier `foundation`): the Vantage design system (A-003). Tokens, fonts, theme and the
reference components are added in M5b WI-3..WI-6. The package exports `.` and `./styles.css` (ADR 0043).
Design values change only in `src/tokens/tokens.json`; run `bun run gen:tokens`.
`tokens.ts` exports every token group as a name list and type (`colorTokens`, `spacingTokens`, `radiusTokens`, `shadowTokens`, `blurTokens`, `opacityTokens`, `durationTokens`, `easingTokens`, `typeStyles`) and `cssVar(name)` for any of them (WI-8).

## Components (M5b WI-4)
Props and `vt-*` class names match `reference/vantage`. Import from `@umbra/ui-kit`.
- `Button`, `ButtonProps`: `variant` (`filled` is the one azure command per view), `size`, `icon`. An icon-only button needs `aria-label` or `aria-labelledby` (type error otherwise, dev warning at runtime).
- `Chip`, `ChipProps`: toggle button, `selected` maps to `aria-pressed`; `ChipGroup`, `ChipGroupProps`: `role="group"` with `label` and optional `aria-describedby`.
- `Badge`, `BadgeProps`, `Tone`: one status word with a dot; `neutral` is the default.
- `AffiliationTag`, `AffiliationTagProps`, `Affiliation`: APP-6D frame shape and fill; children replace the default word.
- `Alert`, `AlertProps`, `AlertTone`: `role="alert"` for danger and warning, `status` otherwise.

## Components B (M5b WI-5)
- `Panel`, `PanelProps`: glass container floating over the map; a `region` labelled by its title; `width` 320px default, 400 for tables. Never place one on another glass layer.
- `Card`, `CardProps`: opaque tonal container; `level` 1 to 3, `variant="outline"`.
- `TextField`, `TextFieldProps`: label, `help` (wired through `aria-describedby`), `mono`, `invalid` (sets `aria-invalid`).
- `Toggle`, `ToggleProps`: `role="switch"`; needs a `label`, `aria-label` or `aria-labelledby`, and takes an optional `aria-describedby` (type error otherwise, dev warning at runtime). `ThemeToggle`, `ThemeToggleProps`: "Day theme" switch over `useTheme`; needs a `ThemeProvider`. `THEME_STORAGE_KEY` ("umbra.theme") and `parsePreference(value)` (`ThemePreference | undefined`) are exported for storage adapters (`@umbra/settings`).
- `Slider`, `SliderProps`: native range input; the `format`ted value is shown and exposed as `aria-valuetext`; arrow keys are native.
- `Tabs`, `TabItem`, `TabsProps`: `tablist` (optional `label` names it; optional `id` derives tab ids `${id}-tab-${value}` and `aria-controls` `${id}-panel-${value}`, give the panel that id) with roving tabindex; the count follows the label after a space (name "Entities 12"); Left, Right, Home and End move focus and select; `count` above 9999 shows "9999+".

## Components C (M5b WI-6)
- `CommandBar`, `CommandBarProps`: the page `banner` (a `header`; render it directly in the body, nested in `main` or `section` it is no longer a banner landmark). The `clock` is a `timer` named "Scenario clock" (", paused" when `paused`; `paused` needs a `clock` and must be paired with a visible word, a "Resume" button or a "Paused" Badge in the children, since colour is never the only signal); cyan while running, `ink-muted` when paused, tabular figures. `brand` defaults to "Umbra". `floating` is glass; glass `Chip`s and `Panel`s inside a floating bar drop to `surface-2` (no glass on glass). A `Readout` inside the bar renders compact (label over a 20px value, no tile) so it fits the bar height; its `unit` is fine, a `delta` row is not supported there (it would not fit 48px). The bar exposes its height as the custom property `--vt-cmdbar-height` (48px) on the `header`, for shells that place things below it. On the Day theme the glass bar is light and the Readout labels (`ink-muted`) sit on glass: the known glass-contrast WARN of `check:contrast`, by design (ASM-509).
- `Readout`, `ReadoutProps`: a `dl` (label is the term, value the definition); `live` is cyan; the unit follows the value after a thin space; a `delta` may carry a `trend` (glyph plus a hidden word, never colour alone).
- `EntityList`, `EntityListProps`, `EntityRow`, `EntityRowProps`: a labelled `listbox` of `option` buttons. Click, Enter and Space call `onSelect`; Up, Down, Home and End move focus between rows without selecting. Every row stays a Tab stop. Rows must contain no interactive content (an option has presentational children). `stale` dims the row and shows the word "Stale" in place of the status Badge; the affiliation is spelled out for assistive technology. Not built: virtualization and a single roving tab stop (M8, ASM-337). `EntityRow` also takes `badges` (`readonly { label, tone? }[]`, non-interactive Badges after the status, class `vt-entity-badges`) and `presentational: true` (WI-10, ASM-939/943): the same content in a `div` (`vt-entity-static`, no padding, no hover) with no button and no `option` role, for a `VirtualList` row that owns the option; `selected` and `onSelect` are ignored when `presentational` is set (a plain optional prop, so existing callers and spreads of `EntityRowProps` keep compiling).

## Components D (M8 WI-1, ADR 0073)
- `Table`, `TableProps`, `TableColumn`: a real `table` named by its required `caption` (`captionHidden` keeps it for assistive technology only). `columns` are `{ key: keyof Row, label, align?: "start" | "end", mono? }`; headers are `th scope="col"` in label style; `null` and `undefined` cells render empty. `rowKey` gives each row a stable key. `empty` shows one full-width row when `rows` is empty and the headers stay. `dense` tightens the rows. Mono cells never wrap (`white-space: nowrap`); a table wider than its container needs a scrolling wrapper from the caller. `render?: (row) => ReactNode` on a column (WI-13, ASM-956, additive; the default stays `String(row[key])`) draws a custom cell such as a Badge; the column `key` still names the column and keeps its `mono` and `align` classes. No sorting or virtualization.
- `Select`, `SelectProps`, `SelectOption`: a native `select` in a `vt-field` (label via `htmlFor`, `help` through `aria-describedby`, `invalid` sets `aria-invalid`); `onChange` receives the option value as a string.
- `AppNav`, `AppNavProps`: a `nav` landmark named "Pages" by default (`label` overrides) with one `AppLink` per `NavItem` of the provider; the item whose `path` equals `currentPath` exactly gets `aria-current="page"`. Horizontal, so it fits inside a `CommandBar`.
- `AppLink`, `AppLinkProps`: an anchor whose `href` is `to`. A plain primary click calls `navigate` and prevents the browser navigation; modified clicks (ctrl, meta, shift, alt), the middle button, `target` other than `_self`, `download`, and a caller `onClick` that called `preventDefault` are left to the browser.
- `NavigationProvider`, `NavigationProviderProps`, `NavItem`, `useAppNavigate`: the router seam (ADR 0046). The app passes `navigate`, `currentPath` and `items`; ui-kit imports no router. `useAppNavigate`, `AppNav` and `AppLink` throw outside a `NavigationProvider`.

## Components D (M8 WI-2, ADR 0072)
- `VirtualList`, `VirtualListProps`: a fixed-height windowed list. `role` selects the variant: `"listbox"` (`activeIndex`, `selectedIndex?`, `onActiveIndexChange(index | null)`, `onActivate`) or `"log"` (`followEnd?`). Common props: `label` (accessible name), `count`, `rowHeight` (`"row-sm"` 28px for log lines, `"row-md"` 36px for single-line entity rows, `"row-lg"` 56px for two-line rows; tokens `--row-sm`, `--row-md`, `--row-lg`), `renderRow(index)` (presentational content only: no role, button or `aria-selected`, the list owns the option semantics), `getRowId(index)`, `overscan` (default 8), `observeSize` (default `ResizeObserver`; tests inject a fake). The scroller is the role element and the single tab stop; rows are absolutely positioned inside a `[data-virtual-sizer]` of `count * rowHeight` px, carry `aria-setsize`/`aria-posinset` and, in a listbox, `role="option"`. Listbox keys: Arrow Up/Down, Home, End, PageUp/PageDown move the active row (`aria-activedescendant`, shown as an outline; selection does not follow focus), Enter and click call `onActivate`, and the caller sets `selectedIndex` (every option states `aria-selected`; the selected row has the EntityRow look). The active row is always mounted. A log is `aria-live="off"` (list and listitem semantics; announcements come from an app status region) and with `followEnd` stays at the newest row until the user scrolls away, and resumes at the end. Rows are `type-data` (mono 13/18); style them by content, not by height. `virtualize?: boolean` (default `true`, WI-12, ASM-953): `false` mounts every row with the same classes, ids, ARIA and keyboard model (PageUp/PageDown included), for short lists whose rows must all be in the DOM; the element does not change when the flag toggles. A listbox with `count` 0 is not a tab stop (`tabindex="-1"`).
- `useElementHeight` is internal (not exported); the pure maths (`windowRange`, `nextActiveIndex`, `scrollToReveal`, `ROW_HEIGHT_PX`) sits in `src/model/`.
