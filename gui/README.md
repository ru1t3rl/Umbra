# Umbra GUI

React + TypeScript client of the Umbra engine (A-002, D-36). It is a pure client: it talks to `umbra serve` over REST and the WebSocket stream and imports no engine source (REQ-A-4). Rules: `gui/CLAUDE.md`, `docs/frontend-architecture.md`. Status: M5b (live map and the Vantage design system) is complete pending the human screenshot review below.

## Prerequisites
- Bun at the version in `package.json` (`packageManager`), and Node.js LTS (22 or 24) for the node-launched tools (Playwright, orval, dependency-cruiser).
- `bun install` (online the first time; `bun install --frozen-lockfile` afterwards).
- For e2e only: `bunx playwright install chromium` once, and the release engine binary `cargo build -p umbra-cli --release --locked` (`target/release/umbra`, or set `UMBRA_BIN`).

## Run the dev server against `umbra serve`
```sh
# terminal 1, from the repository root: the engine with a scenario in stepped mode
cargo run -p umbra-cli --release -- serve --bind 127.0.0.1:7878 --scenario examples/scenarios/walking_skeleton/scenario.toml --clock stepped --start
# terminal 2
cd gui && bun run dev      # http://localhost:5173
```
- `/` is the live map, `/showcase` the design-system reference page. The theme starts in Ops and the switch in the command bar changes to Day without a reload.
- The browser talks to its own origin. Vite proxies `/api/` (REST and the stream, `ws: true`) to `UMBRA_ENGINE_URL` (default `http://127.0.0.1:7878`), so the server's `Host` and `Origin` checks pass and no CORS is needed. `public/config.json` (`{ "engineUrl": "" }`, empty = same origin) is read at runtime; set `engineUrl` for a deployed build that talks to another origin, and an optional `"basemap": { "styleUrl": "..." }` for an online map style.
- Without the engine the map shows the offline basemap and the connection alert reconnects with backoff.
- Stepping from a script instead of the GUI: use the generated client from `@umbra/data` (e2e and scripts only) or `curl`, see `docs/api.md`.

## Verify (gate 15)
```sh
cd gui && bun run verify     # the ordered list of checks, stops at the first failure
scripts/gates.sh --gui       # from the repository root: the full engine gate plus gate 15
```
`verify` runs `gen:api --check`, `gen:tokens --check`, `check:tokens`, `check:contrast`, `check:licenses`, `typecheck`, `lint`, `check:layout`, `check:deps`, `test`, `build` and `test:e2e` (ADR 0044). After an engine contract change run `bun run gen:api` and commit the result; never edit `features/data/src/generated/` or `features/engine-stream/src/generated/` by hand.

## End-to-end tests
- `bun run test:e2e` builds the app with `--mode e2e` and serves it with `vite preview`. Project `ui` needs no engine; project `engine` (`e2e/engine/`) starts a real headless `umbra serve` from `target/release/umbra` (or `UMBRA_BIN`) and steps `walking_skeleton` through the generated client.
- Headless Chromium uses SwiftShader for WebGL; no GPU is needed. Run it on Linux: the screenshot baselines are Linux-only and another platform fails loudly.
